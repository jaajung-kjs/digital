# 사내망 배포 절차

이 문서는 **사내망(K-Cloud) 서버에서 실행할 순서**다. 한 번 훑고 그대로 따라 하면 된다.

## 0. 이번 배포의 전제

- 스키마가 전면 재구축을 지나 **옛 DB 와 이어지지 않는다** → 데이터베이스를 비우고 새로 세운다.
- 마이그레이션은 기준선 하나(`20260827000000_init`)로 접혀 있다. 빈 DB 에 한 번에 선다.
- 백엔드 컨테이너가 뜰 때 **`migrate deploy` → `seed` → 서버** 순으로 자동 실행된다.
  즉 **볼륨만 비우면** 스키마·초기 데이터는 알아서 채워진다.

시드가 채우는 것: `admin` 계정 · 조직(본부 15 · 사업소 34) · 분류 4 · 장비 품목 23(포트 42) ·
설비 품목 6 · 케이블 그룹 5 · 케이블 종류 17.
**시드가 채우지 않는 것: 변전소 · 기준정보(노임·제비율)** — 아래 4단계에서 사람이 넣는다.

## 1. 준비

```bash
# 되돌릴 길 — 지우기 전에 뜬다
docker exec <postgres 컨테이너> pg_dump -U postgres -d <옛 DB 이름> > backup-$(date +%F).sql

# .env 확인 (없으면 .env.prod.example 을 복사)
#   DB_NAME=digital_next          ← 옛 값(ict_digital_twin)이면 반드시 고친다
#   JWT_ACCESS_SECRET / JWT_REFRESH_SECRET  ← openssl rand -hex 32 로 새로 발급
#   CORS_ORIGIN=http://<사용자가 브라우저에 치는 주소>:8080
#   FRONTEND_PORT=8080            ← 80 은 DPI 가 막는다
```

기준정보 원본 파일도 손에 둔다(4단계에서 올린다):
`backend/src/v2/__tests__/fixtures/wage-2026H1.hwp` · `overhead-2026.xlsx` — 최신본이 있으면 그것.

## 2. 교체

```bash
docker compose down
docker volume ls | grep -E 'postgres_data|uploads_data'   # 이름 확인
docker volume rm <프로젝트>_postgres_data <프로젝트>_uploads_data
#   사진 파일은 uploads 볼륨에, 그 경로는 DB 에 있다 — 한쪽만 지우면 깨진 사진이 남는다

docker compose up --build -d
docker logs -f <backend 컨테이너>     # 아래 세 줄이 보이면 성공
#   [seed:next] admin user created
#   [seed:next] org created — 본부 15, 사업소 34
#   {"event":"server.start","port":3000,"env":"production"}
```

## 3. 접속 확인

브라우저에서 `http://<주소>:8080` — **평문 주소로 연다는 점이 중요하다.**
`crypto.randomUUID` 처럼 https·localhost 에서만 있는 API 에 기대면 여기서 죽는다
(그래서 id 는 `newId()` 한 곳에서 만들고 폴백을 둔다 — guardrail 시험이 지킨다).

`admin` / `admin123` 으로 로그인 → **비밀번호를 바로 바꾼다.**

## 4. 사람이 넣는 것

1. **기준정보** → 상단 「기준정보」 → 노임단가(hwp) · 제비율(xlsx) 업로드
2. **변전소** → 조직 트리에서 본부 › 사업소 위에 손을 올리고 `＋` → 이름 입력
   (시드는 변전소를 넣지 않는다 — 어느 사업소가 어느 변전소를 맡는지는 해마다 바뀐다)
3. 없는 전력지사도 같은 방법으로 트리에서 더한다(시드는 자료로 확인된 곳만 담았다)

## 5. 스모크 체크 (5분)

- 로그인 → 조직 트리에 본부 15개
- 변전소 하나 만들기 → 평면도 → 「층 추가」 → 「배치」로 설비 하나 놓기 → **저장**
- 현황·선번장·계통 탭이 각각 뜨는지
- 기준정보에 직종 노임이 보이는지
- 브라우저 콘솔에 빨간 오류가 없는지

## 6. 되돌리기

```bash
docker compose down
docker volume rm <프로젝트>_postgres_data
docker volume create <프로젝트>_postgres_data
# 1단계 백업 복원 후 이전 이미지 태그로 up
```

## 로컬에서 미리 검증하기 (배포 전 권장)

개발 스택과 이름·볼륨이 겹치지 않는 검증용 오버라이드가 있다 — **빈 DB 첫 부팅**을 그대로 재현한다.

```bash
docker compose -f docker-compose.yml -f docker-compose.verify.yml build
docker compose -f docker-compose.yml -f docker-compose.verify.yml up -d
open http://twin.local:8080        # /etc/hosts 에 127.0.0.1 twin.local
docker compose -f docker-compose.yml -f docker-compose.verify.yml down -v
```

`localhost` 로 검증하면 안 된다 — HSTS·CSP·CORS·보안 컨텍스트가 운영과 달라 **헛검증**이 된다.
실제로 이 검증에서만 드러난 배포 차단 버그가 있었다(평문 주소에서 id 생성 실패).
