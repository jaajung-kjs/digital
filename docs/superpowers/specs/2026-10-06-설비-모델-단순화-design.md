# 설비 모델 단순화 — 포트를 걷고 **현장 대장의 모양**으로

> 이 시스템이 답해야 하는 것은 셋이다: **무엇이 몇 대 있나**(현황), **전원이 어떻게 흐르나**(계통),
> **광이 어디서 어디로 이어지나**(선번장·링). 셋 다 **포트 단위의 질문이 아니다.**
> 그래서 포트·설비 품목·내부 결선을 걷고, 엑셀 대장이 이미 쓰는 모양 다섯 가지만 코드에 고정한다.

## 결정 변경 (구현 중)

본문과 이 목록이 어긋나면 이 목록이 맞다. 근거는 각 단계 계획(`docs/superpowers/plans/2026-10-0*-설비-모델-단순화-*.md`)과
용어 정비(`2026-10-07-화면-용어-정비.md`).

## 왜

### 피드백: 「어렵다」, 「초기 입력에 엄두가 안 난다」

발표 후 피드백은 *불편*이 아니라 *어렵고 복잡하다* 였다. 원인은 화면이 아니라 모델의 낟알이다.

지금 모델(capability 메타모델, `2026-07-24-capability-metamodel-rebuild-design.md`)은 물리
인터페이스(L1)를 1급 객체로 다루는 DCIM 모델이다.

```
분류 → 장비 품목(포트 템플릿: 매체·방향·갈래·심선 수) → 설비 품목(14×20 구성 + 내부 결선)
     → 평면도 배치 → 포트 인스턴스 → 케이블(포트↔포트) → 내부 홉(byPosition) → 추적
```

* **의존 사슬** — 앞 단계가 끝나기 전에는 아무 가치도 안 나온다. 현황 하나를 보려 해도
  품목 → 배치를 거쳐야 하고(자산 생성 지점은 `FloorPlanView.tsx:1786`·`InfoTab.tsx:380` 뿐),
  케이블 1가닥에 최소 7번의 조작이 든다.
* **개념 누출** — 현장 화면에 분류/장비 품목/설비 품목/케이블 그룹/케이블 품목/매체/방향/갈래/
  심선 수/경로슬롯/다심 인입/내부 결선이 그대로 보인다. 분전반 하나를 표현하려 해도 관리자가
  「입력 포트 1 + 출력 포트 N(전원·AC) + 계통 스위치」로 **조립**해야 한다.
* **일괄 입력 없음** — 엑셀/CSV 가져오기·붙여넣기·내보내기가 없다.

### 현장 엑셀이 실제로 관리하는 것 (15개 파일 전수 조사)

| 대장 | 한 행 | 규모(직할+원주) |
|---|---|---|
| OFD 선번장 | 코어 1개 (상대국·용도·OTDR) | 약 2,900 코어 |
| 광단국현황·PITR·RTU | 설비 1대 (모델·제작사·년월·S/N) | 수백 대 |
| 분전반 | 차단기 1개 (용량·용도·케이블·SW) | 수백 회로 |
| 계통도 | **도형**(셀 데이터 아님) | — |

현장은 **포트↔포트 연결을 데이터로 적지 않는다.** 랙 U 위치도 적지 않는다. 적는 것은
「설비 목록」과 「번호가 매겨진 행 목록(코어·차단기)」 두 모양뿐이다.

### 종이 검증 (북춘천)

북춘천 관련 엑셀 전부를 이 스펙의 모델에 손으로 옮겼다(설비 51 · 광선로 12 · 코어 행 72 · 연결 40).

* 광 토폴로지는 선번장만으로 정확히 나온다 — RTU 예비회선 경로가 SCADA 회선현황과 **구간 단위로
  일치**하고(북춘천 FL2:9 → 춘천HP:20 → 화천HP:1 → 화천:37 → 철원), 송광치 링 순서가 카드 맵과
  일치한다. 주(코어 1·2)와 예비(7·8)는 별개 경로로 갈라진다 — 그리고 **같은 OPGW 안**이라는
  사실(물리 이중화 아님)이 덤으로 드러난다.
* 자리가 없던 열은 이 스펙에 칸으로 반영했다: 코어 끝 표기(WEST/EAST·Tx/Rx), 코어 상태(단선·
  사용불가), 측정 끝·날짜별 측정, 단국 판 위치(구춘천 25–48), 같은 국 안 광선로, 구간 정보,
  철거예정·교체예정, 모델·제작사·년월·S/N, 수정이력.
* **채널 계층(E1/T1 — 소형광 선번장, PITR 회선 경로의 `(PTPU:2)`)은 의도적으로 범위 밖이다**
  (사용자 결정: 채널 단위 추적·채널 정보 불필요).

## 원칙

1. **코드에 고정하는 것은 현장 대장의 모양 다섯 가지** — 랙, 설비, 회로 행, 광선로(+코어 행),
   국 내 연결. 어떤 종류든 이 모양을 쓸 수 있다. **종류 key 로 갈라지는 코드는 0** 을 유지한다
   (기존 가드레일 그대로). 새 설비 종류는 관리자 화면에서 이름·공량만 넣으면 된다.
2. **연결도는 선언하지 않고 파생한다** — 링 이름·망 레코드를 두지 않는다(본부마다 이름이
   다르고, 본부 사이 링은 주인이 없다). 주·예비는 쓰는 코어가 달라서 저절로 갈린다.
3. **한 사실은 한 행** — 광선로의 코어는 두 국이 **같은 행을 공유**한다. 패치는 한 번만 적힌다.
   선번장·계통·추적은 이 행들을 보여 줄 뿐이다.
4. **층마다 홀로 가치가 난다** — 설비만 넣어도 현황, 광선로만 넣어도 선번장, 회로만 넣어도
   계통. 앞 층이 다 끝나야 뒤 층이 의미를 갖는 사슬을 만들지 않는다.
5. **판정은 `@twin/core` 한 곳** — 서버가 최종 판정, 프론트는 같은 함수로 미리 보인다 (§6 서약 유지).

## 모델

### 마스터 (관리자)

```
분야         Category      key, 이름, 순서                   — 구조·통신·전원·공조 … (지금 분류)
랙 종류      RackType      key, 이름, 순서, 노무코드, 자재단가, 공량(신설·철거·이설)
설비 종류    EquipmentType key, 이름, 분야, 순서, 노무코드, 자재단가, 공량(신설·철거·이설)
케이블 종류  CableType     key, 이름, 매체, 순서, 노무코드, 자재단가, m당 공량(신설·철거)
```

* **매체**는 코드의 고정 어휘다: `power`(전원) · `comm`(통신) · `ground`(접지) · `fiber`(광선로).
  이름·색은 core 상수 한 곳(`CABLE_MEDIA`). `fiber` 는 광선로에만, 나머지는 국 내 연결에만 쓴다.
* **종류에는 깃발이 없다.** 수용형·수량형·광단자·계통 스위치·선로 관리 스위치 모두 없다 —
  담는 것은 항상 랙, 담기는 것은 항상 설비이고, 회로·판은 데이터가 있으면 생긴다.
* 종류별 사용자 정의 필드는 두지 않는다(예전에 실제로 쓰인 것이 둘뿐이라 이미 걷었다 —
  `catalog/types.ts` 의 `COMMON_ASSET_FIELDS` 주석).

#### 설비는 항상 랙에 든다

`Equipment.rackId` 는 필수다. 벽에 붙은 함체는 「벽부함」 같은 랙 종류로 담는다. 랙은 현황
대수에 섞이지 않는다 — 현황은 **설비를 종류별로** 센다.

함체 자체가 장비인 것(UPS반·분전반함·충전기반)은 **랙 + 같은 이름의 설비** 두 행이다.
모델에 예외를 두지 않고, 화면이 「같은 이름의 설비 함께 만들기」를 한 동작으로 제공한다.
랙 이름과 설비 이름은 **이름 공간이 따로**라 같은 이름이 허용된다.

#### 번호 행 두 가지 — 회로와 코어

현장 대장의 「번호가 매겨진 행 목록」이다. **개수만 정하면 1..N 행이 생긴다**(모델). 화면은 코어는 코어 수로,
차단기는 개수 칸 없이 「차단기 추가」 한 줄씩(②-b) — 둘 다 같은 개수 규칙으로 저장된다.

| | 회로 | 코어 |
|---|---|---|
| 붙는 곳 | 설비 (`Equipment.circuitCount` 를 정하면 생김, 기본 0) | 광선로 (`coreCount`) |
| 행이 드는 값 | 차단기의 값: 갈래·전압·용량·상·개폐·용도 | 선로의 값: 상태·주/예비(공유) · 용도·비고(끝별) · 측정(끝별) |
| 「어디로 이어지나」 | 연결이 답한다 | 연결이 답한다 |

* 회로는 **어떤 설비에나** 열려 있다 — 분전반·UPS·충전기·소내전원반, 그리고 나중에 생길
  어떤 종류든. 종류에서 허용할 필요가 없다.
* **용도·비고는 끝마다 따로**(2026-10-07 결정) — 현장 선번장은 국마다 제 쪽에서 적는다(북춘천 「PTP(춘천-북춘천) WEST」 /
  (구)춘천 「… EAST」, Tx/Rx 뒤바뀜, 「그 아래 FDF 의 3~6코어만」 같은 한 국 비고). 상태·주/예비는 물리 사실이라 공유.
  선번장은 이 국 끝의 용도·비고를 보이고 고친다.
* 코어의 「사용 중」은 **저장하지 않는다** — 그 코어 끝에 연결이 있는가로 파생한다.
  코어 상태는 물리 상태(정상·단선·사용불가)만 적는다.
* 회로 끝과 코어 끝은 이 시스템에 남는 **유일한 포트성 개념**이다. 템플릿·매체·방향·위치 수가 없다.

#### OFD 의 판(슬롯) = 그 OFD 에 꽂힌 광선로 끝들

OFD 를 위한 특별한 객체는 없다. 광선로 끝이 `단자 설비 = OFD-1, 판 2, 시작번호 25` 를 가리키면
OFD-1 의 상세에 판 2 가 나타나고, 코어 i 의 어댑터 번호는 `시작번호 + i − 1` 이다.

```
OFD-1  (판 수 8)
 판 1  (구)춘천–북춘천   24C  ■■■■□□□□…
 판 2  (구)춘천–화천     24C  ■□□□□□□□…
 판 3  (비어 있음)
```

* `Equipment.panelCount`(선택)는 빈 판 표시에만 쓴다. 어떤 설비에나 열려 있다.
* 한 판에 48심이 들어와 1–24·25–48 로 두 선로를 받는 것은 같은 판 번호에 시작번호가 다른 끝 둘이다.
* 같은 국 안 광선로(춘천HP MCR실)는 두 끝의 국이 같은 광선로다.

#### 국 내 연결 — 국 안의 물리 케이블은 전부 여기

| 현장 | 표현 |
|---|---|
| 분전반 회로 1 → 송광치 | 연결(회로 1 ↔ 설비 송광치, F-CV 5.5sq 12m) |
| 코어 5 → 송광치 C1 WEST (점퍼) | 연결(코어 5 의 이 국 끝 ↔ 설비 송광치 "C1 WEST", 광 점퍼코드) |
| 중계국 패치 | 연결(L1 코어 9 끝 ↔ L2 코어 9 끝) — **한 번만 적힌다** |
| L3 ↔ 송광치 LAN | 연결(설비 ↔ 설비) |
| UPS 회로 3 → 분전반 P1 | 연결(회로 3 ↔ 설비 분전반 P1) |

* 전원의 방향은 저장하지 않는다 — **회로 행을 가진 쪽이 공급**이다.
* 통신 연결(설비↔설비)은 **선택 입력**이다. 넣지 않아도 다른 기능은 전부 동작한다.
* 국을 넘는 것은 **광선로뿐**이다. 연결은 항상 한 국 안에서 끝난다.

                  @@unique([substationId, name]) }

                  @@id([equipmentId, no]) }             // id 없음 — 자연 키

model LinkEnd   { id, linkId (Cascade), end ('A'|'B'),

                  @@unique([circuitEquipmentId, circuitNo])   // NULL 은 겹쳐도 되므로 부분 인덱스가 필요 없다
                  @@unique([coreLineId, coreNo, coreSide])
                  // 한 끝 한 종류는 CHECK(LinkEnd_one_kind · label_only_equipment) }

  배포는 새 마이그레이션 기준선 + 빈 DB 시드.

## 파생 (저장하지 않는 것)

모두 `@twin/core` 의 순수 함수다.

| 파생 | 정의 |
|---|---|
| **현황 집계** | 국(또는 지사·본부) 범위의 설비를 분야 → 종류로 묶어 센다. 랙은 세지 않는다. |
| **코어 사용 여부** | 그 코어의 A 끝 또는 B 끝에 연결이 있으면 사용. |
| **선번장 행의 자국·대국 연결** | 이 국 쪽 코어 끝의 연결 반대편 / 상대 국 쪽 코어 끝의 연결 반대편. |
| **판 목록** | 그 설비를 단자 설비로 가리키는 광선로 끝들, 판 번호·시작번호 순. |
| **전원 트리** | 설비 → 그 설비의 회로 → 회로 끝의 연결 반대편 설비 → … 재귀. 교류·직류를 함께 받는 공급 설비는 차단기를 교류 모선·직류 모선(그리고 교류/직류 미지정)으로 나눠 펼친다. 순환이면 그 지점에서 멈추고 「상위 설비 공급」(흐린 중립 배지), 이미 위에서 펼친 설비·모선은 「상단 참조」, 입력 연결이 없는 설비는 「입력 전원 미지정」. |
| **광 경로** | 설비 끝 연결 → 코어 끝 → 같은 코어의 다른 끝 → (패치 연결 → 코어 끝 → 다른 끝)* → 연결 → 설비. 코어 끝마다 연결이 최대 하나라 **코어에서 출발한 사슬은 유일**하다(설비에서 출발하면 그 설비의 코어 끝 연결 수만큼). |
| **경로 묶음** | (양 끝 설비 쌍, 지나는 광선로 목록, 주/예비)가 같은 경로들을 한 선으로 — Tx/Rx 두 코어가 한 선이 되고, 주·예비나 다른 경로는 별개 선이 된다. |
| **링** | 설비를 마디, 광 경로를 간선으로 둔 그래프의 고리. 이름 없음 — 표시용 이름이 필요하면 설비 비고·이름으로 충분. |
| **이중화 경고** | 같은 설비 쌍 사이의 주·예비 경로가 같은 광선로를 지나면 경고. |
| **설계서 항목** | 변경안의 전/후 차이: 랙·설비 신설·철거·이설(대), 연결·광선로 신설·철거(m — 연결은 `lengthM`, 광선로는 `lengthKm×1000`). 이설 = 랙: 국 변경, 또는 전·후 모두 놓인 랙의 층 변경 · 중심이 문턱(전·후 너비·깊이 중 최솟값의 절반)보다 멀리 이동(놓기·배치 해제·크기 조절은 이설 아님) / 설비: 랙 변경. 랙째 옮기면 랙 이설 1건이고 안의 설비는 이설로 세지 않는다. |

## 저장

### 변경안 = 공사 단위 (국 단위 워킹카피 폐지)

* 변경안 하나가 **여러 국**을 담는다. 조직 트리에서 국을 옮겨 다니며 편집하면 변경이 계속 쌓인다.
  필요한 국의 기준 데이터는 방문할 때 읽어 base 에 더한다(base ⊕ overlay 구조·zundo 재사용).
  국의 워킹카피 응답은 그 국 행에 더해 **참조**를 싣는다 — `farLinks`(이 국 광선로의 상대 끝 코어에 닿은 연결),
  `refEquipment`(그 연결·광선로 끝이 가리키는 남의 국 설비의 이름), `refLines`(이 국 연결이 가리키는 남의 국 광선로).
  참조는 읽기 전용이고 그 국을 들르면 제 것으로 바뀐다.
* 삭제: `suspendAndLoad`·`resumeSuspended`·`dropSuspended`, `readOnly()=suspended!==null`,
  남의 국 가닥 잠금, `peerResolve.cableOwner`, `useAssetRefs`, 슬롯 개명.
* 저장 바는 변경 수 합계와 변경이 걸친 국 이름을 보인다(국별 수는 아니다). 이탈 가드는 변경안 전체의 `dirtyCount()` 를 본다.
* 설계서는 **변경안 전체**의 차이로 산출한다 — 두 국에 걸친 광선로 공사가 설계서 1부다.
* 변경안은 지금처럼 **브라우저에만** 있다(서버 저장 공사·준공 반영은 범위 밖).

### 커밋 — 엔드포인트 하나, 원자

* `PUT /api/v2/commit` 하나. 본문은 엔티티별 `creates`·`updates`·`deletes`
  (rack·equipment·fiberLine·coreMeasurement·link — 연결 끝은 연결 본문에 포함) + 회로·코어는 `updates`
  만(생성·삭제는 아래 개수 규칙) + `baseVersions`(행별 updatedAt).
  국별 `PUT /substations/:id/commit` 은 삭제.
* 건드린 국들의 advisory lock 을 **국 id 정렬 순서로** 잡는다(교착 방지). tx timeout·P2002→409·
  OCC 409 + 충돌 다이얼로그는 지금 것을 재사용한다.
* 회로·코어 행 생성/삭제는 `circuitCount`·`coreCount` 변경의 결과로 **서버가** 맞춘다
  (클라이언트도 같은 core 함수로 미리 펼친다). 늘리면 뒤에 붙이고, 줄일 때 잘려 나갈 행에
  연결·측정이 있으면 거부.
* 커밋마다 `ChangeLog` 1행.
* 저장 권한은 지금처럼 관리자.

### 검증 규칙 (`@twin/core` 한 곳)

1. 랙 이름·설비 이름은 각각 국 안에서 유일.
2. 설비의 랙은 같은 국.
3. 연결의 양 끝은 모두 연결의 국 안: 설비 끝은 그 국의 설비, 회로 끝은 그 국 설비의 회로,
   코어 끝은 **그 끝(A|B)의 국이 연결의 국**인 코어.
4. 연결 끝은 정확히 한 종류(설비 | 회로 | 코어 끝). 설비 끝에만 표기가 있다.
5. 회로 끝·코어 끝은 각각 연결 최대 하나(DB 부분 유일 인덱스로도 보장).
6. 연결 케이블 종류의 매체는 `power|comm|ground`, 광선로 케이블 종류의 매체는 `fiber`.
7. 광선로 끝의 단자 설비는 그 끝의 국 설비.
8. 연결의 두 끝이 같은 것을 가리키면 거부.

### 삭제 규칙 (결정적, 변경안에 보이게 펼친다)

| 지우는 것 | 함께 |
|---|---|
| 설비 | 그 설비의 회로, 그 설비·회로에 닿은 연결 삭제 (설계서에 케이블 철거로 잡힘). 그 설비를 단자로 가리키던 광선로 끝은 단자 설비·판을 비움. |
| 랙 | 안에 설비가 있으면 거부 — 먼저 옮기거나 지운다. |
| 광선로 | 코어·측정, 코어 끝에 닿은 연결 삭제. |
| 회로·코어 (개수 축소) | 연결·측정이 있으면 거부(위). |

## 화면

### 메뉴

`설비 현황` · `품목 관리` · `기준정보` (②-b). 품목 관리는 한 화면 — 왼쪽 목록 `설비 품목 · 랙 품목 · 케이블 품목 · 분야`
에서 고르면 오른쪽에 같은 모양의 단순 표(이름·분야·노무유형·공량·단가, 키는 숨김·자동 생성). 기준정보는
`노임단가 · 제비율 · 올린 기록` 탭. **옛 설비 품목 편집기(구성 그리드·내부 결선)·포트 편집기는 화면째 삭제.**

### 설비 현황 — 국 탭: 현황 · 선번장 · 전원 계통 · 평면도 / 지사·본부 탭: 현황 · 광 계통도

* **현황** — 위: 품목별 대수(「품목별 / 랙별」 보기). 아래: 랙 → 설비 두 단계 표(이름 자연 순서).
  랙·설비를 여기서 바로 추가(평면도 불필요). 랙 추가에 「같은 이름의 설비 함께 만들기」.
  지사·본부의 현황은 범위 집계(저장된 것만 — 저장 전 변경은 국 탭에서 본다).
  상세 패널 탭: **정보 · 연결 · 점검·고장 · 사진**. 차단기(있을 때)·슬롯(광선로 끝이나 슬롯 수가 있을 때)은
  정보 탭의 카드다. 비어 있으면 카드 대신 「차단기 추가」·「슬롯 수」 동작만 둔다 — **품목별 화면 분기 없음.**
  **「이력」 탭은 아직 없다** — ChangeLog 는 커밋마다 쓰이지만 읽는 길(API·화면)은 이월이다.
* **선번장** — 이 국에 닿은 광선로를 접속 설비 → 슬롯 순 블록으로. 블록 머리: 접속 설비 · 슬롯 · 어댑터 범위 ↔ 상대국,
  선로명·긍장·케이블 품목. 행: 코어 · 어댑터 · 자국 접속 · 대국 접속 · 상태 · 주/예비 · 회선 내역 · 비고 ·
  최근 측정(1310/1550 손실·거리·측정일). 광선로 추가 = 상대국 + 코어 수. 코어를 누르면 측정 이력,
  블록마다 **측정 일괄 입력**, 연결이 있는 코어에 **중계경로**.
* **전원 계통** — 보기 둘: **차단기 대장**(공급 설비별 차단기 표 — 현장 분전반 시트 모양: 전압·CB번호·용량·부하명·
  전원케이블·비고)과 **계통도**(입력 전원 → 차단기 → 부하 트리, §파생 「전원 트리」). 교류/직류 거르기.
* **평면도** — 선택 기능. **랙만** 배치. 연결은 그 설비가 든 랙 사이 선으로. 배경 도면 유지.

### 연결 — 방법은 하나

끝을 고르는 곳은 **이 국의 설비·차단기·코어 끝 목록(검색)** 이다 — 설비 상세 연결 탭, 차단기 표, 차단기 대장,
선번장 코어 네 입구가 같은 「연결 추가」 상자를 연다. 연결은 항상 국 안에서 끝나므로
국 목록이 결정적이다. 도면은 고른 것을 강조할 뿐이다. 평면도가 선택 기능이 되었으므로
「도면이 유일한 입구」(`2026-09-17-케이블-연결-통일-design.md`) 규칙을 이 규칙으로 **대체**한다.
연결 세션(`connectSession.ts`)의 「값 하나」 원칙은 유지한다 — 끝 타입만 바뀐다.

### 토폴로지·추적 (지사·본부 범위)

지사·본부의 **광 계통도** 탭 — 국 지도(광선로 = 간선) 위에 광 경로를 그린다. 주·예비는 별개 선(실선/점선),
주/예비 미지정은 옅은 강조색, 이중화 경고 표시. 옆 패널: 링 · 이중화 경고 · 경로 미완결(까닭) · 회선 목록.
데이터는 `GET /api/v2/nodes/:id/network`(읽기 전용, 최대 8 바퀴 번짐, 넘치면 `truncated`) — 저장 전 변경은 그 위에 겹친다.
선번장 코어의 **중계경로** 상자는 한 회선의 사슬을 세로로 펼치고 머리에 G7 표기 요약
(`북춘천(OFD:9)-춘천HP(OFD:20)-화천HP(OFD:1)-화천(OFD:13)-철원`)을 단다.
`topology/layout.ts` 배치는 재사용, `trace/internalLinks.ts`·byPosition·포트 기반
`buildTraceGraph` 는 삭제하고 위 「광 경로」 파생으로 대체.

### 설계서

`computeReport`·`computeEstimate` 골격 유지. 입력만 새 엔티티로 바꾼다
(`ReportKind` 에 `rack-*` 추가, `cable-*` 는 연결·광선로 공통). 저장 바의 「설계서」가 변경안 전체로 연다.
화면: 산출 조건(공사명·공사기간·계약방법·산재보험료 기준) · 산출 내역(국별 묶음) · 노무유형별 공량·노무비 ·
원가계산서(재료비·노무비·경비 → **순공사원가** 소계 → 일반관리비·이윤·부가가치세 → 총공사비) · A4 인쇄.
금액은 줄마다 원 단위 반올림(core `materialCostOf`·`laborCosts`). 기준정보가 없으면 「기준정보 미등록」,
길이·단가·노무유형이 비면 0 이 아니라 그 사정을 적는다.
**범위 밖:** 설계서 보관(서버 저장), 엑셀/HWP 내보내기, 수량산출서, 일위대가.

## 검증

* **core 단위** — 검증 규칙 8개, 삭제 펼침, 번호 행 펼침/축소 거부, 파생 전부(현황·판·전원 트리·
  광 경로·링·이중화 경고), 설계서 산출(랙째 이설 1건 포함).
* **백엔드 통합** — 여러 국 원자 커밋, 행 OCC 409, 락 정렬, 부분 유일 인덱스 위반 → 409,
  ChangeLog 기록. 픽스처는 안정 prefix + 공유 스윕(beforeAll+afterAll).
* **가드레일** — 종류 key 리터럴 비교 금지 유지, `Port`·`Assembly`·`portKind` 식별자 잔존 금지,
  매체 어휘는 `CABLE_MEDIA` 한 곳.
* **완료 기준 — 북춘천 브라우저 시나리오**
  1. 현황 종류별 대수가 종이 검증 표와 일치.
  2. 선번장 블록(상대국·선로명·긍장·코어별 용도·측정)이 엑셀과 일치.
  3. RTU 예비회선 광 경로 추적이 SCADA 회선현황과 구간 단위로 일치.
  4. 송광치 링이 고리로 그려지고, PTP 주(1·2)·예비(7·8)가 별개 선 + 이중화 경고.
  5. 분전반 회로 대장이 엑셀 분전반 시트와 일치, 전원 트리가 전원계통도와 일치.
  6. 두 국에 걸친 광선로 신설 → 설계서 1부(광케이블 m + 양 끝 점퍼).

  **결과와 자료의 한계(2026-10-08):**
  1 — 검증하지 못했다. 정답 픽스처(종이 표)가 없고, 시드의 북춘천 설비 수(29)는 종이 표(51)와 다르다(시드 범위 =
  통신실 설비). 2·3·6 — 충족(e2e·시드 시험). 3 은 화천 어댑터를 선번장(13)대로 적고 G7 의 37 은 문서 불일치로 기록.
  4 — 소프트웨어는 충족(core 송광치 픽스처: 경로 9 · 링 1 · 경고 1). 직할 시드에는 링 패치가 없어 그래프가 나무라
  **링 0** 이고, 화면은 「완결된 회선으로는 링이 나타나지 않습니다(경로 미완결 n)」로 말한다(미완결 경로 22). 5 — 대장
  모양은 현장 시트를 따랐으나 직할 분전반 시트가 없어 자료 대조는 못 했다((구)춘천 시드와 일치).

## 단계

브랜치에서 진행한다. ②가 끝나야 앱이 다시 온전히 돈다. 구현 계획은 단계별로 쓴다.

| 단계 | 내용 | 끝나면 |
|---|---|---|
| ① 모델·저장 | 스키마 기준선, core(엔티티 타입·검증·삭제 펼침·번호 행), 커밋 서비스·라우트, ChangeLog, 마스터·직할 시드 | 데이터가 들어가고 원자 저장됨 (API 수준) |
| ② 현황 | 워킹카피(공사 단위), 현황 표·집계, 상세 패널, 종류 관리 화면 2개, 평면도(랙 배치), 연결 | 첫 가치: 현황 + 앱 복구 |
| ②-b 프론트 정리 | 메뉴 셋(품목 관리 통합·기준정보 탭), 용어(차단기·슬롯·실장 설비), 차단기 한 줄씩 추가 | 화면 말 정비 |

## 결정 기록 — 고려했다가 버린 것

| 안 | 버린 이유 |
|---|---|
| 포트를 모든 설비에 유지 | 현장 질문 중 포트 단위가 없다. 회로·코어 끝만 남긴다. |
| 망(링·회선) 명사 | 이름 표준이 없고 본부 사이 링은 주인이 없다. 코어 사슬에서 파생하면 주·예비도 갈린다. |
| 국을 넘는 연결 + 경유 목록 | 코어 행이 국 사이 연결 그 자체다. 경유 목록은 같은 사실의 두 번째 표현. |
| 코어 행의 끝에 설비·패치를 직접 저장 | 패치가 양쪽 행에 두 번 적혀 어긋날 수 있고, 점퍼·전원 케이블이 다른 곳에 살아 설계서가 두 곳을 본다. → 국 내 연결 한 표. |
| 전원을 설비↔설비 연결로 | 예비 차단기·조명처럼 반대편 설비가 없는 회로를 못 담는다. → 회로 행. |
| 수용형·수량형·광단자 깃발 | 「모든 설비는 랙에 든다」 — 국 → 랙 → 설비 고정 두 단계면 깃발이 필요 없다. |
| 채널표(설비의 번호 행) | 사용자 결정: 채널 정보 불필요. |
| v3 병행 격리 후 전환 | 지킬 운영 데이터가 없어 병행의 이득이 없고, 지우려는 개념을 두 벌 유지하게 된다. |
