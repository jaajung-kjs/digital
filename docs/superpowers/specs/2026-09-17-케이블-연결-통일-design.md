# 케이블 연결을 **한 가지 방식**으로 — 연결 세션과 오버레이

> 끝점을 고르는 방법은 하나다: **도면에서 설비를 눌러 포트를 고른다.**
> 다른 층·다른 국은 특별한 문이 아니라 **평소처럼 옮겨 가서** 고른다.
> 끝나면 **시작한 화면으로 돌아온다.**

## 왜

케이블을 잇는 **쓰기**는 이미 한 곳이다(`cableActions.ts` 의 `connectCable`). `aPortId`/`bPortId`
를 쓰는 자리를 전수로 훑으면 거기와 설비 품목의 내부 배선(`placeAssembly.ts:117`, 사람 손짓이
아니다) 둘뿐이다. **제각각인 것은 쓰기가 아니라 「어떻게 잇게 하느냐」다.**

### 단계 번호가 뒤로 간다

`FloorPlanView.tsx:496-513` 이 단계를 상태 조합에서 유도하는데, 그 조합이 왕복한다.

| 사용자가 하는 일 | 상태 | 화면 |
| --- | --- | --- |
| 출발 설비 클릭 | `picker` 열림 | **2/3** 오른쪽 판에서 포트를 고르세요 |
| 출발 포트 고름 | `firstPortId` 섬 | **3/3** 경로를 그리고 반대쪽 설비를 클릭 |
| 도착 설비 클릭 | `picker` **다시 열림** | **2/3** ← 번호가 뒤로 간다 |
| 도착 포트 고름 | `CABLE_STAGED` | **1/3** 이을 설비를 클릭하세요 |

실제 걸음은 다섯인데 셋으로 세고 있어서 `2/3` 가 두 번 나온다. 그리고 `CABLE_STAGED`
(`cableTool.ts:114`)가 `firstPortId` 만 비우고 `armed` 를 유지하므로 — 연속 연결을 위한
설계다 — **이었다는 말 없이** `1/3` 로 돌아간다. 방금 완성한 일이 실패한 것처럼 보인다.

### 종류를 고를 자리가 진입점마다 다르다

도면에서 시작하면 도구바에서 **먼저** 고른다. 포트에서 시작하면 고를 기회가 없고,
`FloorPlanView.tsx:479-485` 가 대신 집는다.

```
if (selectedGroupKey !== port.medium) {
  const first = cableGroups.find(g => g.key === port.medium)?.categories[0];
  if (first) cableDispatch({ type: 'SET_CATEGORY', categoryId: first.id });
}
```

그 매체 그룹의 **첫 품목**을 말없이 집는다. 광 포트면 「OPGW(광복합가공지선)」이 되는데,
정작 이으려던 것이 「광점퍼코드」여도 그렇다. 매체가 이미 맞으면 **직전에 쓰던 품목**을
조용히 재사용한다. 둘 다 화면에 아무 말이 없다 — 고친 적 없는 값이 저장된다.

### 다른 층은 못 잇고, 다른 국은 딴 방식으로 잇는다

`RemoteEndpointModal` 이 존재하는 까닭이 이것이다 — 그 머리 주석이 직접 적어 두었다:
「층을 옮기면 고르던 끝점이 따라가 버려서 층 넘는 케이블은 아예 만들 수가 없었다.」 즉
**버그를 모달로 우회한 것**이다. 그 결과 고르는 방법이 둘이 되었다(도면 클릭 / 목록 탐색).

게다가 그 문의 이름이 「**다른 변전소에서** 찾기」다(`FloorPlanView.tsx:1973`). 같은 국의
다른 층을 이으려는 사람이 그 문을 열 이유가 없다. 그리고 그 버튼은 `firstPortId` 가 있을
때만 나타나므로, 상대가 먼저 떠오르는 일에는 순서가 거꾸로다.

### 대국 연결에 의미 없는 경로가 붙는다

`handleRemotePortSelect`(`FloorPlanView.tsx:1409`)가 `draftPath` 를 그대로 넘기는데,
반대쪽이 이 도면에 없으므로 그 꺾은점들은 **어디로도 가지 않는 선**이다.

### 표에서는 아예 못 잇는다

선번장·계통의 `PeerCell` 은 `onSelect(assetId, portId)` 로 **선택만 옮긴다**. 빈 칸은
`PeerCell.tsx:54` 에서 눌리지 않는 글자로 끝난다 — 심선 24개를 잇는 자리에서 잇는 길이 없다.

## 무엇을 만드나

### ① 연결 세션 — 「지금 케이블을 잇는 중」이라는 사실 하나

```ts
/** 이을 곳을 고르는 중 — 이 값이 있으면 오버레이가 뜬다. */
interface ConnectSession {
  /** 출발 끝점. **이것이 정해지는 순간 세션이 선다.** */
  from: { portId: string; label: string; substationId: string };
  /** 케이블 품목 — 오버레이에서 언제든 바꾼다. */
  categoryId: string | null;
  /** 끝나면 **돌아갈 자리** — 시작한 화면 그대로. */
  origin: { substationId: string; view: ViewMode; floorId: string | null };
  /** 다른 국에 다녀오는 중이면 담아 둔 워킹카피(아래 ④). */
  suspended: SuspendedCopy | null;
}
```

**`origin` 이 「시작한 화면」이다.** 평면도에서 시작했으면 평면도로, 계통에서 시작했으면
계통으로 돌아온다 — 이을 곳을 고르러 어디를 다녀왔든.

### ② 진입점은 **출발을 정하는 방법**일 뿐이다

| 진입점 | 출발을 정하는 방법 | 지금 |
| --- | --- | --- |
| 평면도 | 「케이블」 무장 → 설비 클릭 → 포트 고르기 | 있음 |
| 포트 탭 | 빈 포트 클릭 | 있음(평면도로 끌려간 뒤 3/3 상태) |
| 선번장 빈 칸 | 그 심선의 자국/대국 칸 클릭 | **새로 생김** |
| 계통 빈 부하 칸 | 그 회로의 부하 칸 클릭 | **새로 생김** |

출발이 정해지면 세션이 서고 오버레이가 뜬다. **그 뒤는 어디서 왔든 똑같다.**

### ③ 오버레이 — 화면을 옮겨도 계속 떠 있다

머리줄(`PageHeader`) 아래, 뷰 탭 줄 위에 선다. **탭을 옮겨도 층을 옮겨도 국을 옮겨도 남는다.**

```
┌──────────────────────────────────────────────────────────────────┐
│ 케이블 연결   출발 OFD · 슬롯 1 · 광 1                             │
│ 종류 [광점퍼코드 ▾]   도착할 설비를 도면에서 누르세요      [취소]    │
└──────────────────────────────────────────────────────────────────┘
```

다른 국에 다녀오는 중이면 그 사실과 돌아가는 길을 적는다.

```
┌──────────────────────────────────────────────────────────────────┐
│ 케이블 연결   출발 (구)춘천S/S · OFD · 슬롯 1 · 광 1                │
│ 북춘천S/S 는 **읽기 전용** — 이을 포트만 누르세요   [돌아가기][취소]  │
└──────────────────────────────────────────────────────────────────┘
```

- **단계 번호가 없다.** 지금 무엇을 기다리는지 한 줄로 말한다. `1/3`~`3/3` 과 `cableStep` 은 사라진다
- **종류가 오버레이에 있다.** 도면을 보는 동안에도 언제든 바꾼다 — 진입점마다 다르던 자리가 하나가 된다
- **취소는 늘 한 자리에 있다**

### ④ 다른 국은 **보류하고 다녀온다** — 예외가 아니라 같은 방식

세션 중 조직 트리에서 다른 국을 고르면, 지금 국을 **버리지 않고 담아 둔다**.

```ts
interface SuspendedCopy {
  substationId: string;
  overlays: Overlays;
  baseVersions: Record<string, string>;
}
```

`Overlay<T>` 는 `{ creates, updates, deletes }` 라는 **순수한 값**이고(`store/overlay.ts:1`),
`load()` 는 `saved`·`baseVersions`·`overlays` 를 갈아 끼울 뿐이다(`workingCopyStore.ts:96`).
그러니 따로 담아 뒀다 도로 얹으면 그대로 살아난다.

```
A국에서 시작 (변경 7건)  ──트리에서 B 클릭──▶  A를 담아 두고 B를 읽기 전용으로 연다
                                                      │
                          B 도면에서 설비·포트 고름 ◀───┘
                                     │
                                     ▼
          load(A) → 담아 둔 overlays·baseVersions 를 도로 얹는다
          connectCable(출발, 고른 포트) → **A에 스테이징**
          origin 화면으로 돌아간다
                                     │
                                     ▼
                       A국 · 변경 7건 + 새 케이블 1건
```

**얻는 것 둘.**

1. 케이블이 **시작한 국의 것**이 된다. 지금은 `stageCableCreate` 가 그때 로드된 국에 쌓여
   **B의 것**이 되어 반대다
2. **유령 포트가 사라진다.** 저장 안 한 설비의 포트에서 시작해도 A로 돌아오면 그 설비가
   복원된다 — 지금은 국을 옮기는 순간 출발이 사라진다

**정하는 것 넷.**

- **다녀오는 국은 읽기 전용이다.** 저장 바·배치 도구·케이블 도구·삭제를 끈다. 고르러 간 것이지
  고치러 간 것이 아니다. 혹시 인라인으로 고친 값이 남아 있으면 **돌아올 때 묻는다**
  (「북춘천S/S 의 변경 2건이 버려집니다」) — 조용히 버리지 않는다
- **보류는 한 겹만.** B에서 또 C로 가면 그냥 C로 간다(A 보류는 유지). 어디에 있든 오버레이가
  「돌아가기」를 걸어 둔다
- **`baseVersions` 는 보류 때 것을 그대로 쓴다.** 되돌아올 때 서버 자료를 새로 읽지만, 편집은
  보류 때 본 것을 바탕으로 했으므로 그 버전이 맞다 — 그 사이 남이 고쳤으면 저장할 때 충돌이
  정직하게 잡힌다(`ConflictDialog` 가 이미 있다)
- **되돌리기(undo) 이력은 지운다**(`zundo` 의 `temporal.clear()`). 국을 넘나든 이력을 섞으면
  무엇이 되돌려질지 모른다

### ⑤ 그리면서 잇기는 **뺀다**

지금은 출발을 정한 뒤 도면을 여러 번 눌러 꺾은점을 찍고 마지막에 설비를 눌러 이었다. 그
하나 때문에 **도면 클릭의 뜻이 둘**이 되고(꺾은점 / 도착), 그 애매함이 「도면에서 고르기」와
「목록에서 고르기」를 갈라 놓았다.

**경로는 이은 뒤에 그린다.** 선을 끌어 꺾고 점을 더블클릭해 지우는 기능이 **이미 있다**
(`CablePathEditor`). 잇는 일과 모양을 다듬는 일은 원래 다른 일이다.

그래서 **도면 클릭의 뜻이 하나로 고정된다: 이을 설비를 고른다.**

치르는 값: 여러 가닥을 같은 경로로 그릴 때 이은 뒤 각각 꺾어야 한다. 대신 연결 흐름에서
분기가 **전부** 사라진다.

### ⑥ 이은 뒤

- **시작한 화면(`origin`)으로 돌아간다.** 보류가 있으면 먼저 복원한다
- 오버레이가 「이었습니다」를 잠깐 적는다 — 지금은 말없이 `1/3` 로 돌아가 실패처럼 보인다
- **「이어서 또 잇기」**를 켜 두면 세션은 살아 있고 **출발만 비운다**. `origin` 도 그대로라,
  계통에서 시작했으면 계통으로 돌아와 다음 회로 칸을 누르면 된다
- 안 켰으면 세션이 끝난다

### ⑦ 세션 밖으로 나가면 — **보류분도 「저장하지 않은 변경」이다**

설비 현황을 떠나면(상단 메뉴로 관리 화면 등으로 이동) 세션은 끝난다. 그런데 보류 중이라면
담아 둔 A의 변경이 **조용히 사라질 자리**가 여기다: 지금 로드된 것은 B이고 B는 읽기 전용이라
`dirtyCount()` 가 0 이므로, 셸의 이탈 가드(`useUnsavedMark`)가 「변경 N건이 사라집니다」를
띄우지 않는다.

**`dirtyCount()` 가 보류분을 함께 센다.** 그래야 떠나기 전에 묻는 말이 참이 된다 — 이미 있는
가드 하나가 그대로 일한다(새 가드를 만들지 않는다). 「이동」을 고르면 보류분까지 버리고,
「취소」를 고르면 세션이 그대로 남는다.

복원을 **떠나는 길에 끼워 넣지 않는다.** 복원은 A를 다시 읽는 비동기 일이라, 화면이 사라지는
중에 하면 절반만 끝난 상태가 남는다. 떠날 때는 버리거나 머무는 둘 중 하나다.

### ⑧ 걷어내는 휴리스틱 셋

| 지금 | 뒤 |
| --- | --- |
| `FloorPlanView.tsx:483` 매체 그룹의 **첫 품목을 말없이** 집는다 | 오버레이의 종류 칸이 눈에 보이고, **직전에 그 매체에 쓴 것**이 고른 채로 들어간다. 처음이면 비어 있고 그때는 이을 수 없다 |
| 매체가 맞으면 **직전 품목을 조용히** 재사용 | 같은 값이지만 **화면이 무엇을 골랐는지 말한다** |
| 이은 뒤 말없이 `1/3` 로 리셋 | 「이었습니다」 + `origin` 복귀 + 「이어서 또 잇기」 |

**직전에 쓴 것**은 매체별로 기억한다(`Record<medium, categoryId>`). 화면이 그 값을 고른 채로
보여 주므로 숨은 값이 아니다.

### ⑨ 도착 후보를 거르는 규칙 — **사실이지 짐작이 아니다**

- 도착 후보는 `portKind(출발매체).connectsTo` 가 정한 매체의 포트 중 자리가 남은 것.
  **「같은 매체」가 아니다** — 어휘가 짝을 정한다(`validation/connection.ts:38-41`). 어휘에
  없는 매체는 예전 규칙(같은 매체끼리)으로 둔다
- 종류 목록은 출발 매체의 그룹으로 거른다 —
  `cableMedium !== undefined && a.medium !== cableMedium`(`validation/connection.ts:42`)이
  이미 그렇게 요구한다

### ⑪ 덤 — 케이블 값 편집 세 벌을 하나로

「케이블의 `specParams` 한 칸을 고친다」가 같은 글로 세 곳에 복사돼 있다.

| 파일 | 이름 |
| --- | --- |
| `FiberRegisterView.tsx:40~85` | `CableFieldInput` |
| `PowerRegisterView.tsx:44~85` | `CableFieldInput` |
| `SelectedPortCard.tsx:61~82` | `CableValueControl` |

셋 다 같은 일을 한다: 숫자면 `Number()`, 빈 값은 `null`, `NaN` 이면 무시, 무변경이면 무시,
스토어에서 케이블을 다시 읽어 `specParams` 를 합쳐 `stageCableUpdate`. `CableValueField`
하나로 합친다.

### ⑫ 대국 케이블은 **여는 쪽 국의 것**이라는 사실을 화면에 적는다

케이블은 `substationId` 를 갖고(`commit.service.ts:748` — 한쪽 끝만 이 국이면 받는다),
반대쪽 국에서는 서버가 실어 주는 `V2CableRef`(`types.ts:210`)로 **읽기만** 된다. 지금은 그
말이 화면에 없어 「왜 안 고쳐지지」가 된다 — 대국에서 온 가닥에 **「(구)춘천S/S 의 케이블」**
을 적고, 누르면 그 국으로 가는 길을 둔다.

## 손대지 않는 것

- **`connectCable` 의 검증**(`validateConnection`) — 규칙은 core 의 것이고 이미 한 곳이다
- **설비 품목의 내부 배선**(`placeAssembly.ts` → `stageAssemblyCables`) — 사람 손짓이 아니라
  선언에서 펴지는 것이고, 이미 저장 때 `validateAssembly` 를 통과했다
- **경로점 편집**(`CablePathEditor`) — 그대로. 이제 경로를 붙이는 **유일한** 자리다
- **케이블 삭제**(`deleteCableWithConfirm`) — 이미 한 곳이다

## 어떻게 확인하나

- **`connectSession` 시험**(새로) — 전이가 값으로 닫힌다: 출발이 정해지면 세션이 서고,
  `suspendFor(B)` 뒤 `restore()` 가 **같은 overlays 를 돌려주고**, `finish()` 가 `origin` 을
  그대로 돌려준다
- **`cableToolReducer` 시험**(`__tests__/cableTool.test.ts`) — 세션으로 옮겨 간 동작의 시험도
  함께 옮긴다. 남는 것(케이블 선택)만 여기 남는다
- **새 시험** — 「진입점이 달라도 세션의 상태가 같다」: 도면·포트 탭·선번장·계통에서 연 네
  세션이 같은 `from`·같은 종류 목록·같은 도착 후보를 갖는다
- **새 시험** — 종류가 비어 있으면 이을 수 없다(휴리스틱이 사라졌다는 증거)
- **새 시험** — 보류 중 `dirtyCount()` 가 **보류분을 함께 센다**(⑦의 구멍이 막혔다는 증거)
- **`npm run build`** + 프론트·core 시험 전부
- **눈으로** — 네 진입점에서 차례로 열어 **같은 오버레이**가 뜨는지 / 층 탭을 옮겨도 출발이
  남는지 / 다른 국에 다녀와도 **변경 건수가 그대로**인지 / 이은 뒤 **시작한 화면**으로
  돌아오는지 / 「이어서 또 잇기」가 출발만 비우는지

## 순서 — 쪼갤 수 있는 단위

1. **`connectSession` + 오버레이 + 도면·포트 탭 진입점** — 같은 국 안에서 완결된다.
   `cableStep`·하단 안내줄·그리면서 잇기·종류 자동선택이 여기서 사라진다
2. **층 넘기** — 층 탭을 옮겨도 세션이 남는다(워킹카피가 같으므로 ①만으로도 거의 된다)
3. **국 넘기(보류·복원)** — `suspend`/`restore`. 여기서 `RemoteEndpointModal` 이 삭제된다
4. **선번장·계통 빈 칸 진입점** — 새 기능
5. **⑪ 케이블 값 편집 합치기** — 연결 흐름과 별개의 중복
6. **⑫ 대국 케이블 소유 표시**

4~6 은 떼어낼 수 있다 — 통일 자체는 1~3 으로 선다.
