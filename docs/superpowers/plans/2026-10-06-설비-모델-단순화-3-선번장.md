# 설비 모델 단순화 ③ 선번장 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 국 탭에 「선번장」을 더해 OFD 선번장 엑셀을 대체한다 — 단자 설비 → 슬롯 블록, 코어 행(어댑터 번호·자국 연결·대국 연결·상태·주/예비·용도·최근 측정), 측정 이력·일괄 측정 입력, 광선로 추가·편집·삭제.

**Architecture:** 모델·저장 경로는 ①②에서 이미 있다(FiberLine·Core·CoreMeasurement, 커밋 하나, 워킹카피 `fiberLines`·`coreMeasurements`·`updateCore`, 서버 `farLinks`·`refEquipment`). ③은 (1) core 에 선번장 파생 순수 함수 하나, (2) 직할 시드에 코어별 용도·상태·비고를 엑셀에서 싣기, (3) 화면(탭·블록 표·대화상자)을 더한다. 백엔드 API 변경은 없다.

**Tech Stack:** TypeScript, `@twin/core`(vitest), React 18 + zustand 워킹카피, Tailwind 시맨틱 토큰, Python(openpyxl, 추출 스크립트), Playwright.

**Spec:** `docs/superpowers/specs/2026-10-06-설비-모델-단순화-design.md` — §모델「번호 행」「OFD 의 판(슬롯)」, §파생「코어 사용 여부」「선번장 행의 자국·대국 연결」「판 목록」, §화면「선번장」, §검증 완료 기준 2.

## Global Constraints

- **화면 말:** 판 → 슬롯, 회로 → 차단기. 「종류」「자산」「회로」「판」「안의 설비」 금지(가드 `frontend/src/v2/__tests__/uiWords.guardrail.test.ts` 가 막는다). 쓰는 말: 광선로·코어·슬롯·어댑터·자국 연결·대국 연결·용도·주/예비·측정.
- UI 를 고치기 전에 `frontend/src/components/ui/CONVENTIONS.md` 를 먼저 읽고 따른다(본문 `text-sm`·라벨 `text-xs`, 시맨틱 토큰, 공용 컴포넌트, 표 행 `TABLE_ROW h-7`, 행 액션 호버, 삭제는 `tone="danger"` + `useConfirm`, IME 안전).
- **판정은 core 한 곳** — 행 펼침 `rowsForCount`, 검증 `validateState`, 삭제 펼침 `expandDeletes`. 화면은 그 결과를 보여 줄 뿐 규칙을 다시 쓰지 않는다. 종류 key 분기 0(가드레일).
- 「사용 중」은 저장하지 않는다 — 코어 끝에 연결이 있는가로 파생(스펙). 코어 상태는 `CORE_STATUSES`(정상·단선·사용불가)만.
- 어댑터 번호 = 그 끝의 `startNo + no − 1`.
- 남의 국 연결(`farLinks`)은 **읽기 전용 참조**다 — 대국 연결 칸은 보이기만 하고 고치지 않는다(그 국을 들르면 제 것이 된다).
- 백엔드 API·스키마 변경 없음. core 를 고치면 `npm run build -w @twin/core`.
- 개발 DB 는 워크트리 `backend/.env` → `digital_simplify`. `digital_next` 금지. docker compose 금지. `git stash` 금지. dev 서버(5173/3000)는 이미 떠 있다 — 끄지 않는다.
- 프론트 타입체크 `npx tsc -b`(frontend/), 루트 빌드 `npm run build`.
- 커밋 메시지 끝: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## 결정 변경 (2026-10-07, 사용자)

- **코어 용도·비고는 끝별(A·B)로 저장**한다 — `Core.purpose/note` → `aPurpose·aNote·bPurpose·bNote`. 상태·주/예비는 공유. Task 2 가 스키마·core·백엔드·프론트 타입·시드를 함께 바꾼다(Task 2b). `SheetRow.purpose/note` 는 **그 블록 끝**의 값이고, `peerPurpose`(상대 끝 용도, 읽기 참고)를 더한다. Task 3 의 용도·비고 편집은 그 블록 side 의 필드를 고친다.

## Review Focus

1. **같은 국 안 광선로(두 끝 국이 같음)는 블록이 둘**이다(A 끝 블록·B 끝 블록, 자국/대국 연결이 서로 뒤바뀐다). Task 1 시험.
2. **단자 설비가 비어 있는 끝**(OFD 삭제로 비워졌거나 아직 안 정함)도 사라지지 않고 「단자 미지정」 묶음에 나온다. Task 1 시험 + Task 3 화면.
3. **코어 수를 줄일 때 잘려 나갈 코어에 연결·측정이 있으면 거부**하고 아무것도 바꾸지 않는다(까닭을 말한다). Task 4 시험.
4. **대국 연결은 고칠 수 없다** — 대국 칸에 잇기·지우기 단추가 없다. 상대 국을 아직 안 들렀어도 `farLinks` 로 이름이 보인다. Task 3 시험.
5. **일괄 측정 입력에서 빈 줄은 측정을 만들지 않고**, 숫자가 아닌 값은 그 칸에서 막는다(저장 전 표시). Task 5 시험.

### Task 1: core — 선번장 파생 `lineSheet`

**Files:**
- Create: `packages/core/src/model/lineSheet.ts`
- Test: `packages/core/src/model/lineSheet.test.ts`
- Modify: `packages/core/src/index.ts`(내보내기)

**Interfaces:**
- Consumes: `ModelState`(core `model/types.ts` — 이미 lines·cores·links 를 담는다; 측정이 없으면 이 함수 인자로 따로 받는다), `LinkEndRef`, `endRefKey`.
- Produces:

```ts
export type LineSide = 'A' | 'B';
export interface SheetMeasurement { measuredOn: string | null; loss1310: number | null; dist1310: number | null; loss1550: number | null; dist1550: number | null }
export interface SheetRow {
  no: number;
  jack: number;                       // startNo + no - 1
  near: LinkEndRef | null;            // 이 국 끝 코어에 닿은 연결의 반대편 끝
  nearLinkId: string | null;
  far: LinkEndRef | null;             // 상대 끝 코어에 닿은 연결의 반대편 끝(같은 국 선로면 그 끝)
  farLinkId: string | null;
  status: string; role: string | null; purpose: string | null; note: string | null;
  latest: SheetMeasurement | null;    // 이 국 끝(side) 측정 중 measuredOn 가장 최근(없으면 null; 날짜 null 은 가장 오래된 것으로)
  measurementCount: number;           // 이 코어의 양 끝 측정 수 합
}
export interface SheetBlock {
  lineId: string;
  side: LineSide;                     // 이 국 쪽 끝
  equipmentId: string | null;         // 이 끝의 단자 설비(없으면 null → 「단자 미지정」)
  panel: number | null; startNo: number;
  peerSubstationId: string;           // 상대 끝 국(같은 국 선로면 자기 국)
  peerEquipmentId: string | null; peerPanel: number | null; peerStartNo: number;
  name: string | null; lengthKm: number | null; cableTypeId: string; coreCount: number;
  rows: SheetRow[];
}
export function lineSheet(input: {
  substationId: string;
  lines: { id: string; cableTypeId: string; coreCount: number; name: string | null; lengthKm: number | null;
    aSubstationId: string; aEquipmentId: string | null; aPanel: number | null; aStartNo: number;
    bSubstationId: string; bEquipmentId: string | null; bPanel: number | null; bStartNo: number }[];
  cores: { lineId: string; no: number; status: string; role: string | null; purpose: string | null; note: string | null }[];
  measurements: { lineId: string; coreNo: number; side: LineSide; measuredOn: string | null; loss1310: number | null; dist1310: number | null; loss1550: number | null; dist1550: number | null }[];
  links: { id: string; a: LinkEndRef; b: LinkEndRef }[];   // 이 국 연결 + farLinks(합친 것)
  equipmentOrder: (equipmentId: string) => string;          // 블록 정렬 키(보통 설비 이름) — 화면이 준다
}): SheetBlock[];
```

규칙:
1. 이 국에 닿은 끝마다 블록 하나(같은 국 선로는 A·B 두 블록).
2. 정렬: 단자 설비 있는 블록 먼저 — `equipmentOrder(equipmentId)` → `panel`(null 은 뒤) → `startNo`; 단자 미지정 블록은 맨 뒤, 그 안은 상대 국 id → 선로 id(안정 정렬).
3. 코어 행은 `cores` 에서 그 선로의 것만, `no` 오름차순. 코어 행이 없으면(아직 펼치기 전) `rowsForCount` 로 1..coreCount 의 기본 행(상태 `DEFAULT_CORE_STATUS`)을 만든다.
4. `near`: 코어 끝 `{kind:'core', lineId, no, side}` 를 가진 연결을 `links` 에서 찾아 반대편 끝. `far` 는 상대 side 로 같은 방식. 끝마다 연결은 최대 하나(검증 규칙 5)이므로 첫 일치.
5. `latest` 는 이 블록 side 의 측정만.
