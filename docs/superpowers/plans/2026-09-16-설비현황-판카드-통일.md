# 설비 현황 네 탭 골격 통일 (`ViewCard`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 설비 현황의 네 탭(현황·평면도·선번장·계통)과 상세 패널이 **하나의 판 컴포넌트(`ViewCard`)** 를 써서, 좌측 기준선·도구바 높이·검색 위치가 화면마다 같아지게 한다.

**Architecture:** 회색 바탕(`--bg` #EDEFF1) 위에 흰 카드가 뜬다. 그 카드의 **회색 머리 띠가 곧 도구바**다 — 왼쪽 첫 칸은 늘 「범위를 고르는 것」, 오른쪽 끝은 늘 검색. 본문은 두 가지뿐이다: 카드가 스크롤을 쥐는 `scroll`(안쪽 래퍼가 여백을 갖는다)과 자식이 다 쥐는 `fill`(안쪽 여백 0). 벽(`border-l` + 흰 바탕)은 화면 구조(트리·머리줄·뷰 탭 줄)에만 남고 내용에서는 사라진다.

**Tech Stack:** React 18 + TypeScript, Tailwind(시맨틱 토큰), Vitest + @testing-library/react, Zustand(워킹 카피).

**Spec:** `docs/superpowers/specs/2026-09-16-설비현황-판카드-통일-design.md`

## Global Constraints

- **UI 작업 전 `frontend/src/components/ui/CONVENTIONS.md` 를 읽는다.** 이 계획의 모든 클래스·구조는 그 문서를 따른다.
- **타이포:** 본문·값·입력 `text-sm`, 라벨·메타·배지·카운트 `text-xs`. **`text-xs` 미만 금지**(예외는 `PortFaceplate` 9px·`AssemblyGrid` 10px 둘뿐 — 새로 끌어다 쓰지 않는다).
- **색은 시맨틱 토큰만.** 하드코딩 hex, `gray-500` 같은 원시 팔레트 금지.
- **z-index 는 토큰만**(`z-sticky` 등). raw `z-50`·인라인 `style={{ zIndex }}` 금지.
- **모서리는 `rounded`(2px) 하나.** `rounded-full` 만 예외(모양이지 모서리가 아니다).
- **크기는 prop 으로.** `<Button size>`·`<Input size>`·`<Select size>`. `className` 으로 여백·글자를 덮어쓰지 않는다. `className` 은 배치(`flex-1`·`w-full`·`ml-auto`)에만.
- **컨트롤 높이는 `controlSize.ts` 가 정한다** — `sm` = `h-6`(24px), `md` = `h-7`(28px).
- **개발 서버:** DB 는 `docker compose -f docker-compose.dev.yml up -d`, 앱은 `npm run dev`. **`docker compose build` / 기본 `docker-compose.yml` 을 개발 중에 쓰지 않는다.**
- **테스트:** `cd frontend && npx vitest run <경로>` (전체는 `npx vitest run`). 빌드 검증은 `cd frontend && npm run build`.

**Interfaces:**
- Consumes: `cn` (`./cn`), `SelectionScope` (`./SelectionScope`)
- Produces:
  - `export type ViewCardBody = 'scroll' | 'fill'`
  - `export interface ViewCardProps { title?: ReactNode; tools?: ReactNode; actions?: ReactNode; status?: ReactNode; body?: ViewCardBody; onClearSelection?: () => void; bodyRef?: Ref<HTMLDivElement>; children: ReactNode; className?: string }`
  - `export function ViewCard(props: ViewCardProps): JSX.Element`

> **스펙에서 한 가지 줄었다.** 스펙은 `body` 를 `scroll | fill | bleed` 셋으로 적었는데, `fill` 과 `bleed` 는 **DOM 이 똑같다**(둘 다 여백 0 · 자식이 높이를 받는다). 이름만 둘인 값은 부르는 쪽이 고민할 거리만 늘리므로 `fill` 하나로 합친다. 캔버스는 `fill` 을 쓰고, 캔버스가 스크롤 상자를 만들지 않도록 `fill` 이 `overflow-hidden` 을 갖는다(§3.5 「실장도를 품은 탭은 스크롤 상자로 두지 않는다」와 같은 규칙).

```tsx
  it('body="scroll" — 스크롤 상자는 카드가 쥐고 여백은 안쪽 래퍼가 갖는다', () => {
    const { container } = render(<ViewCard body="scroll">본문</ViewCard>);
    const box = container.querySelector('.overflow-auto') as HTMLElement;
    expect(box).not.toBeNull();
    expect(box.className).not.toMatch(/\bp-4\b/);
    expect((box.firstChild as HTMLElement).className).toContain('p-4');

    const box = screen.getByTestId('판').parentElement as HTMLElement;
    expect(box.className).not.toMatch(/\bp-\d/);
    expect(box).toHaveClass('overflow-hidden');

    const { container } = render(<ViewCard><div /></ViewCard>);
    expect(container.querySelector('.overflow-auto')).toBeNull();

    expect(onClear).toHaveBeenCalled();

        <button type="button">줄</button>
      </ViewCard>,
    );

    expect(onClear).not.toHaveBeenCalled();

    expect(screen.getByTestId('상태줄')).not.toBeNull();
  });
});
```

```tsx
import type { ReactNode, Ref } from 'react';
import { cn } from './cn';
import { SelectionScope } from './SelectionScope';

/**
 * 본문이 스크롤을 어떻게 쥐는가 — §1.7-b 의 두 가지를 그대로 옮긴 것이다.
 *
 * - `scroll` — **카드가 스크롤 상자**를 쥔다. 여백은 그 **안쪽 래퍼**가 갖는다: 스크롤
 *   상자에 직접 주면 `sticky` 머리글이 그만큼 내려가 붙고, 그 틈으로 지나가는 행이 비친다.
 * - `fill` — **자식이 다 쥔다.** `TableCard fill` 이 제 스크롤을 갖거나(현황), 스크롤이
 *   아예 없거나(캔버스). 안쪽 여백은 **0** 이다 — 카드는 이미 바깥 여백(`gap-3 p-4`) 뒤에
 *   서 있으므로 한 겹 더 들여쓰면 판이 그만큼 좁아진다.
 */
export type ViewCardBody = 'scroll' | 'fill';

export interface ViewCardProps {
  /** 머리 띠 왼쪽의 **이름** — 「무엇을 보고 있나」가 곧 제목인 카드가 쓴다(상세 패널). */
  title?: ReactNode;
  /** 머리 띠 왼쪽의 **범위를 고르는 것** — 거르개·설비 고르개·갈래, 그리고 판 도구. */
  tools?: ReactNode;
  /** 머리 띠 **오른쪽 끝** — 검색 또는 버튼. 이 자리가 고정이라 네 탭에서 검색의 x 가 같다. */
  actions?: ReactNode;
  /** 카드 **바닥 띠** — `StatusBar`. 지금은 평면도만 쓴다. */
  status?: ReactNode;
  body?: ViewCardBody;
  /** 본문 여백을 눌러도 고른 것을 놓는다(§1.7-d) — 주면 `SelectionScope` 가 선다. */
  onClearSelection?: () => void;
  /** 고른 줄을 화면 안으로 옮길 때 잡는 상자(`useScrollSelectedIntoView`). */
  bodyRef?: Ref<HTMLDivElement>;
  children: ReactNode;
  className?: string;
}

/**
 * 화면의 **판** — 회색 바탕 위에 뜨는 흰 카드 한 장.
 *
 * 예전에는 네 탭(현황·평면도·선번장·계통)이 껍데기를 각자 그렸다. 그래서 좌측 기준선이
 * 0·8·12·16px 네 값으로 갈렸고, 도구바 높이가 32·40·46px 로 달랐으며, 검색이 어떤 탭에서는
 * 맨 왼쪽 어떤 탭에서는 고르개 뒤에 섰다. 같은 일을 하는 자리가 넷이면 그중 하나는 반드시
 * 어긋난다 — 실제로 하나도 안 맞았다.
 *
 * **머리 띠가 곧 도구바다.** 카드가 줄을 하나 더 얹는 것이 아니라, 이미 있던 도구바가
 * 카드의 머리(`DetailCardHeader` 와 같은 `surface-2` 면, §3.2)로 들어간다 — 세로 크롬이
 * 늘지 않는다. 자리는 둘뿐이다: **왼쪽 첫 칸은 늘 「범위를 고르는 것」, 오른쪽 끝은 늘 검색.**
 *
 *     <ViewCard tools={<Select …/>} actions={<TableSearch …/>} body="scroll">…</ViewCard>
 */
export function ViewCard({
  title, tools, actions, status, body = 'fill', onClearSelection, bodyRef, children, className,
}: ViewCardProps) {
  const hasHead = title != null || tools != null || actions != null;
  /* 머리 띠 높이가 28px 인 `DetailCardHeader` 와 다른 것은 여기에 `size="sm"` 컨트롤(24px)이
     들어서기 때문이다 — 뷰 탭 줄과 같은 32px 로 맞춰 둘이 한 리듬이 된다. */
  const boxClass = body === 'scroll'
    ? 'min-h-0 flex-1 overflow-auto'
    : 'flex min-h-0 min-w-0 flex-1 flex-col overflow-hidden';
  /* `scroll` 에서 ref 는 **안쪽 래퍼**가 받는다 — 여백을 가진 쪽이 곧 내용의 상자다. */
  const inner = body === 'scroll'
    ? <div className="p-4" ref={bodyRef}>{children}</div>
    : children;

  return (
    <div
      className={cn(
        'flex min-h-0 min-w-0 flex-1 flex-col border border-line-strong bg-surface',
        className,
      )}
    >
      {hasHead && (
        <div className="flex h-8 shrink-0 items-center gap-2 border-b border-line-strong bg-surface-2 px-3">
          {title != null && (
            <span className="flex min-w-0 items-center gap-1 truncate text-sm font-semibold text-content">
              {title}
            </span>
          )}
          {tools}
          {actions != null && (
            <div className="ml-auto flex shrink-0 items-center gap-1.5">{actions}</div>
          )}
        </div>
      )}
      {onClearSelection ? (
        <SelectionScope
          onClear={onClearSelection}
          className={boxClass}
          ref={body === 'scroll' ? undefined : bodyRef}
        >
          {inner}
        </SelectionScope>
      ) : (
        <div className={boxClass} ref={body === 'scroll' ? undefined : bodyRef}>
          {inner}
        </div>
      )}
      {status}
    </div>
  );
}
```

```tsx
import { cn } from './cn';

export interface SegmentedItem<T extends string> {
  key: T;
  label: string;
}

export interface SegmentedControlProps<T extends string> {
  items: readonly SegmentedItem<T>[];
  value: T;
  onChange: (key: T) => void;
  'aria-label': string;
}

/**
 * 상호배타 **갈래** — 「같은 자료를 어느 갈래로 볼까」.
 *
 * **탭이 아니다.** 탭은 다른 내용으로 건너가는 것이고, 갈래는 같은 내용을 거르는 것이다.
 * 생김새를 탭과 같이 두면 위계가 읽히지 않는다 — 계통의 `전체·교류·직류` 가 뷰 탭
 * (현황·평면도·선번장·계통)과 똑같은 사각 탭이었고, 도구바 안에 서느라 **상위 탭보다
 * 14px 더 높기**까지 했다.
 *
 * 현업 자료가 이미 갈래로 나뉘어 있다: 강원본부 통신실 전원계통도는 같은 배치도 위에
 * 「전체·AC·DC」 세 장을 따로 그려 두었다.
 */
export function SegmentedControl<T extends string>({
  items, value, onChange, ...rest
}: SegmentedControlProps<T>) {
  return (
    <div
      role="radiogroup"
      aria-label={rest['aria-label']}
      className="flex shrink-0 items-center rounded border border-line"
    >
      {items.map((it) => {
        const on = it.key === value;
        return (
          <button
            key={it.key}
            type="button"
            role="radio"
            aria-checked={on}
            onClick={() => onChange(it.key)}
            className={cn(
              'h-6 border-r border-line px-2.5 text-xs transition-colors last:border-r-0 focus-ring',
              on ? 'bg-info-bg font-medium text-primary' : 'text-content-muted hover:bg-surface-3',
            )}
          >
            {it.label}
          </button>
        );
      })}
    </div>
  );
}
```

```tsx
import { cn } from './cn';

export interface FilterChipProps {
  label: string;
  /** **거르기 전 전체**다 — 걸러 놓고 그 숫자를 다시 세면 칩이 늘 0 이 된다. */
  count: number;
  on: boolean;
  /** 0 이 아닐 때 글자가 위험·주의 색을 쓴다 — 켜져 있을 때는 선택 색이 이긴다. */
  tone?: 'default' | 'danger' | 'warning';
  onClick: () => void;
}

/**
 * 토글형 **거르개** — 「몇 개 있고, 손볼 것이 있는가」를 세면서 동시에 거른다.
 *
 * 머리 띠의 왼쪽 첫 칸에 선다(§3.1). 예전에는 현황 화면 안에서 일회용
 * `<button className="rounded-full …">` 으로 만들어져 있었다 — 「패널 안에서 일회용 카드·
 * 필드를 새로 만들지 않는다」(§0.1)를 어긴 자리였다.
 *
 * 접근 가능한 이름은 **「이름 숫자」** 다(`미점검 39`) — 화면과 시험이 같은 것을 읽는다.
 */
export function FilterChip({ label, count, on, tone = 'default', onClick }: FilterChipProps) {
  return (
    <button
      type="button"
      aria-pressed={on}
      onClick={onClick}
      className={cn(
        /* 머리 띠의 다른 컨트롤과 같은 24px — 줄 높이를 넘기면 띠가 그만큼 두꺼워진다. */
        'inline-flex h-6 shrink-0 items-center gap-1 rounded-full border px-2.5 text-xs transition-colors',
        on ? 'border-primary bg-info-bg text-primary' : 'border-line text-content-muted hover:bg-surface-2',
        !on && tone === 'danger' && count > 0 && 'text-danger',
        !on && tone === 'warning' && count > 0 && 'text-warning',
      )}
    >
      {label} <span className="font-medium tabular-nums">{count}</span>
    </button>
  );
}
```
