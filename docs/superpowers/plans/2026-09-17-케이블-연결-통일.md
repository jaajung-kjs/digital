# 케이블 연결 통일 (연결 세션 + 오버레이) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 케이블 끝점을 고르는 방법을 **하나**로 만든다 — 도면에서 설비를 눌러 포트를 고른다. 다른 층·다른 국은 평소처럼 옮겨 가서 고르고, 끝나면 시작한 화면으로 돌아온다.

**Architecture:** 「지금 케이블을 잇는 중」이라는 사실을 **연결 세션**(`connectSession.ts`, 순수한 값)이 들고, 화면에는 머리줄 아래 **오버레이** 한 줄이 계속 떠 있다. 다른 국으로 갈 때는 워킹카피를 **버리지 않고 담아 둔다**(스토어의 `suspended`) — `Overlay<T>` 가 `{creates, updates, deletes}` 라는 순수한 값이라 도로 얹으면 살아난다. 쓰기는 이미 한 곳(`connectCable`)이라 손대지 않는다.

**Tech Stack:** React 18 + TypeScript, Zustand(+zundo) 워킹카피 스토어, Tailwind(시맨틱 토큰), Vitest + @testing-library/react.

**Spec:** `docs/superpowers/specs/2026-09-17-케이블-연결-통일-design.md`

## 스펙에서 한 가지 옮겼다

스펙 ①은 `suspended` 를 `ConnectSession` 안에 두었다. **구현에서는 스토어가 쥔다.** 까닭:
스펙 ⑦이 요구하는 「`dirtyCount()` 가 보류분을 함께 센다」를 세션(React 상태)에 둔 값으로는
할 수 없다 — 스토어가 그 값을 볼 수 없다. 담아 둔 워킹카피는 **워킹카피 상태**이므로 스토어가
주인인 것이 옳고, 그러면 `dirtyCount()` 가 자연스럽게 함께 센다. 덤으로 **읽기 전용 = 보류 중**
이라는 파생 사실 하나로 끝난다(별도 깃발이 필요 없다).

세션은 「무엇을 잇는 중인가」(출발·종류·돌아갈 자리)만 든다.

```ts
import type { ViewMode } from './useWorkspaceRoute';

/** 출발 끝점 — 이 값이 있으면 「도착을 고르는 중」이다. */
export interface ConnectFrom {
  portId: string;
  /** 오버레이에 적는 이름(`OFD · 슬롯 1 · 광 1`). 짓는 일은 부르는 쪽이 한다. */
  label: string;
  /** 어느 국의 포트인가 — 다른 국에 다녀올 때 「어디로 돌아가나」와 짝이 된다. */
  substationId: string;
  /** 종류 목록과 도착 후보를 거르는 기준. 「같은 매체」가 아니라 `connectsTo` 의 기준점이다. */
  medium: string;
}

/**
 * 끝나면 **돌아갈 자리** — 시작한 화면 그대로.
 *
 * 평면도에서 시작했으면 평면도로, 계통에서 시작했으면 계통으로 돌아온다. 이을 곳을 고르러
 * 다른 층·다른 국을 다녀왔든 상관없다.
 */
export interface ConnectOrigin {
  substationId: string;
  view: ViewMode;
  /** 평면도에서 시작했을 때의 층. 다른 판에서 시작했으면 `null`. */
  floorId: string | null;
}

/**
 * **지금 케이블을 잇는 중이라는 사실 하나.** 이 값이 있으면 오버레이가 뜬다.
 *
 * 담아 둔 워킹카피는 여기 두지 않는다 — 그것은 워킹카피 상태이므로 스토어가 주인이고,
 * 그래야 `dirtyCount()` 가 보류분을 함께 센다(스펙 ⑦).
 */
export interface ConnectSession {
  /** `null` 이면 **출발**을 고르는 중, 있으면 **도착**을 고르는 중. */
  from: ConnectFrom | null;
  categoryId: string | null;
  origin: ConnectOrigin;
  /** 한 번 이은 뒤에도 세션을 살려 둔다 — 출발만 비운다. */
  keepGoing: boolean;
}

export function openSession(origin: ConnectOrigin): ConnectSession {
  return { from: null, categoryId: null, origin, keepGoing: false };
}

/**
 * 출발이 정해졌다 — 종류는 **그 매체에 직전에 쓴 것**이 물려 온다.
 *
 * 예전에는 그 매체 그룹의 첫 품목을 말없이 집었다. 물려 오는 값은 오버레이에 고른 채로
 * 보이므로 숨은 값이 아니고, 그 매체를 처음 쓰면 **비어 있다**(짐작해 채우지 않는다).
 */
export function withFrom(
  s: ConnectSession,
  from: ConnectFrom,
  lastByMedium: Readonly<Record<string, string>>,
): ConnectSession {
  return { ...s, from, categoryId: lastByMedium[from.medium] ?? null };
}

export function setCategory(s: ConnectSession, categoryId: string | null): ConnectSession {
  return s.categoryId === categoryId ? s : { ...s, categoryId };
}

export function setKeepGoing(s: ConnectSession, on: boolean): ConnectSession {
  return s.keepGoing === on ? s : { ...s, keepGoing: on };
}

/** 셋이 다 차야 이어진다 — 종류가 비면 못 잇는다. */
export function canConnect(s: ConnectSession): boolean {
  return s.from != null && s.categoryId != null;
}

/** 이은 뒤 — 이어서 또 이을 생각이면 **출발만** 비우고, 아니면 세션이 끝난다(`null`). */
export function finish(s: ConnectSession): ConnectSession | null {
  return s.keepGoing ? { ...s, from: null } : null;
}
```

```ts
  const kind = args.fromPortMedium ? portKind(args.fromPortMedium) : null;

  const accepts = (m: string) =>
    args.fromPortMedium == null ? true
    : kind ? kind.connectsTo.includes(m)
    : m === args.fromPortMedium;
  const usable = (a: V2Asset) =>
    a.ports.some((p) => accepts(p.medium) && p.id !== args.firstPortId && portHasRoom(p.medium, counts.get(p.id) ?? 0));
  const ids = new Set<string>();
  for (const placed of args.placed) {
    if (withDescendants(args.assets, placed.id).some(usable)) ids.add(placed.id);
  }
  return ids;
}
```

```tsx
 * **종류가 여기 있다.** 진입점마다 다른 자리에 있던 것(도면은 도구바, 포트 탭은 아예 없음)을
 * 한 자리로 모은다 — 도면을 보는 동안에도 언제든 바꾼다.
 */
export function ConnectOverlay({
  session, groups, readOnly, substationName, onCategory, onKeepGoing, onBack, onCancel,
}: {
  session: ConnectSession;
  groups: readonly CableGroup[];
  /** 다른 국에 다녀오는 중 — 그 국은 읽기 전용이다. */
  readOnly: boolean;
  /** 지금 보고 있는 국 이름 — 읽기 전용일 때 그 이름을 적는다. */
  substationName: string | null;
  onCategory: (id: string) => void;
  onKeepGoing: (on: boolean) => void;
  /** 담아 둔 국으로 돌아간다 — 읽기 전용일 때만 있다. */
  onBack?: () => void;
  onCancel: () => void;
}) {
  /* 종류 목록은 **출발 매체의 것만**. 케이블의 매체는 출발 포트의 매체와 같아야 한다
     (`validation/connection.ts:42`) — 거르는 것이 규칙이 이미 말하는 사실이다. */
  const cats = session.from
    ? (groups.find((g) => g.key === session.from!.medium)?.categories ?? [])
    : [];

  return (
    <div className="flex h-9 shrink-0 items-center gap-3 border-b border-line-strong bg-info-bg px-4">
      <span className="shrink-0 text-sm font-semibold text-primary">케이블 연결</span>

      {session.from ? (
        <span className="flex min-w-0 items-center gap-1.5 text-sm">
          <span className="shrink-0 text-xs text-content-muted">출발</span>
          <span className="min-w-0 truncate text-content">{session.from.label}</span>
        </span>
      ) : (
        <span className="text-sm text-content-muted">출발할 포트를 고르세요</span>
      )}

      {session.from && (
        <div className="w-48 shrink-0">
          <Select
            aria-label="케이블 품목"
            size="sm"
            value={session.categoryId ?? ''}
            onChange={(e) => onCategory(e.currentTarget.value)}
          >
            {/* 비어 있으면 못 잇는다 — 짐작해 채우지 않는다(휴리스틱 제거). */}
            <option value="">— 종류를 고르세요 —</option>
            {cats.map((c) => (
              <option key={c.id} value={c.id}>{c.name}</option>
            ))}
          </Select>
        </div>
      )}

      <span className={cn('min-w-0 truncate text-sm', readOnly ? 'text-warning' : 'text-content-muted')}>
        {readOnly
          ? `${substationName ?? '이 변전소'} 는 읽기 전용 — 이을 포트만 누르세요`
          : session.from
            ? '도착할 설비를 도면에서 누르세요'
            : ''}
      </span>

      <div className="ml-auto flex shrink-0 items-center gap-2">
        <Toggle
          checked={session.keepGoing}
          onChange={(next) => onKeepGoing(next)}
          label="이어서 또 잇기"
        />
        {onBack && (
          <Button variant="secondary" size="sm" onClick={onBack}>돌아가기</Button>
        )}
        <Button variant="secondary" size="sm" onClick={onCancel}>취소</Button>
      </div>
    </div>
  );
}
```

```tsx
export interface CableValueFieldProps {
  value: unknown;
  field: { key: string; label: string; type: 'text' | 'number' | 'date' | 'boolean'; unit?: string; options?: string[] };
  /** 다듬은 값 — 바뀐 것이 없거나 수가 아니면 **부르지 않는다**. */
  onCommit: (next: string | number | null) => void;
  /** 모선이 이미 말한 값인가 — 그러면 흐리게(대장의 ditto). */
  muted?: boolean;
}

/**
 * 케이블 하나에 적는 값 한 칸 — 길이·굵기·손실·선로명.
 *
 * **같은 글이 세 곳에 복사돼 있었다**: 선번장(`CableFieldInput`)·계통(`CableFieldInput`)·
 * 포트 상세(`CableValueControl`). 셋 다 같은 일을 했다 — 숫자면 `Number()`, 빈 값은 `null`,
 * `NaN` 이면 무시, 무변경이면 무시. 같은 케이블의 같은 칸인데 검증이 세 벌이라 한 곳만
 * 고쳐지기 딱 좋았고, 그 사고를 이 저장소는 이미 겪었다(`cableActions.ts` 머리 주석).
 *
 * **스토어를 부르지 않는다.** 값을 다듬는 규칙만 모으고 `stageCableUpdate` 는 부르는 쪽이
 * 한다 — `components/ui` 는 v2 스토어를 모른다.
 */
export function CableValueField({ value, field, onCommit, muted }: CableValueFieldProps) {
  const isNumber = field.type === 'number';
  const shown = value === null || value === undefined ? '' : String(value);
  return (
    <InlineEditCell
      value={shown}
      label={field.label}
      unit={field.unit}
      options={field.options}
      muted={muted}
      type={isNumber ? 'number' : field.type === 'date' ? 'date' : 'text'}
      onCommit={(raw) => {
        const next = isNumber ? (raw.trim() === '' ? null : Number(raw)) : (raw.trim() || null);
        /* 수가 아니면 아무 일도 하지 않는다 — 삼키는 것이 NaN 을 저장하는 것보다 낫다. */
        if (isNumber && typeof next === 'number' && Number.isNaN(next)) return;
        if ((value ?? null) === next) return; // 무변경 가드
        onCommit(next);
      }}
    />
  );
}
```
