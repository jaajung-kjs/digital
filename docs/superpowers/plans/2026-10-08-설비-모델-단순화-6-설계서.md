# 설비 모델 단순화 ⑥ 설계서 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 변경안(공사 단위 — 여러 국에 걸친 저장 전 변경) 전체에서 **산출 내역**(랙·설비 신설·철거·이설 대수, 연결·광선로 신설·철거 m)과 **공사비**(재료비·노무비·제비율 → 총공사비)를 산출하는 설계서를 되살린다. 두 국에 걸친 광선로 공사가 설계서 1부.

**Architecture:** core 의 `computeReport`·`computeEstimate`·`assetReportItem`·`cableReportItem`·`materialCostOf` 는 그대로 살아 있다(스펙: 골격 유지). 새로 필요한 것은 **입력** — 새 엔티티의 전/후 차이에서 `ReportItem[]` 을 만드는 core 순수 함수 `designItems` 와 `ReportKind` 의 `rack-*` 추가. 화면은 옛 `ReportPanel`(`git show e5e4ba9e^:frontend/src/v2/components/ReportPanel.tsx`, `reportSelectors.ts`)의 모양을 새 모델에 맞춰 복원한다. 백엔드 변경 없음(카탈로그 응답에 노임단가·제비율 판이 이미 있다).

**Tech Stack:** TypeScript, `@twin/core`(vitest), React 18 + zustand 워킹카피, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-06-설비-모델-단순화-design.md` — §파생「설계서 항목」, §저장「설계서는 변경안 전체의 차이로 산출」, §화면「설계서」, §검증 완료 기준 6.

## Review Focus

1. **랙째 옮기면 랙 이설 1건**이고 안의 설비는 이설로 세지 않는다. 설비만 다른 랙으로 옮기면 설비 이설 1건. Task 1 시험.
2. **설비 삭제가 펼친 연결 삭제**(expandDeletes)도 케이블 철거로 잡힌다 — 변경안의 최종 차이 기준. Task 1 시험.
3. **두 국에 걸친 광선로 신설 = 설계서 1부**: 광케이블 m(긍장 km×1000) + 양 끝 점퍼(연결 lengthM). 긍장이 비면 「길이 미입력」 줄(수량 0)로 남고 합계는 0 — 숨기지 않는다. Task 1·4 시험.
4. **같은 행을 만들었다 지우면** 설계서에 아무것도 없다(최종 차이). 값만 바꾼 연결(길이·케이블 품목 변경)은 철거+신설로 세지 않는다 — 「변경」은 이 단계에서 산출하지 않으며 화면에 「수량 변경은 산출하지 않습니다」 안내. Task 1 시험.
5. 노임단가·제비율 판이 없으면 금액 칸은 0 이 아니라 「기준정보 미등록」으로 막는다(판정 불가 ≠ 0). Task 2 시험.

**Interfaces — Produces:**

```ts
export interface DesignInput {
  before: { racks: DRack[]; equipment: DEquipment[]; links: DLink[]; fiberLines: DLine[] };
  after:  { racks: DRack[]; equipment: DEquipment[]; links: DLink[]; fiberLines: DLine[] };
  rackTypes: LaborType[]; equipmentTypes: LaborType[]; cableTypes: LaborType[];   // { id, name, laborCode, unitPrice, installManDays, removeManDays, relocateManDays }
  substationName: (id: string) => string;
}
export interface DRack { id: string; name: string; substationId: string; rackTypeId: string; floorId: string | null; x: number | null; y: number | null }
export interface DEquipment { id: string; name: string; substationId: string; rackId: string; typeId: string }
export interface DLink { id: string; substationId: string; cableTypeId: string | null; lengthM: number | null; label: string }   // label = 화면용 「A ↔ B」
export interface DLine { id: string; name: string | null; cableTypeId: string; lengthKm: number | null; aSubstationId: string; bSubstationId: string }
export function designItems(input: DesignInput): (ReportItem & { substationIds: string[] })[];
```

규칙:
1. **신설** = after 에만 있는 id, **철거** = before 에만 있는 id. 둘 다 있으면 **이설** 판정만(아래), 그 밖의 값 변경은 산출하지 않는다(Review Focus 4).
2. **랙 이설** = 국·층·좌표(x,y) 중 하나라도 바뀜. **설비 이설** = `rackId` 가 바뀜. 랙이 이설되어도 그 안 설비의 `rackId` 는 그대로이므로 설비 이설로 세지 않는다(자연히 1건 — Review Focus 1).
3. 연결 → `cableReportItem('cable-install'|'cable-remove', label, 케이블 품목, lengthM)`. 광선로 → 같은 함수, 길이 = `lengthKm × 1000`(m), 이름 = 선로명 또는 「A국–B국」. 케이블 품목 없음 → 「품목 미지정」 줄(공량 0, 옛 `unresolvedCableItem` 과 같은 뜻).
4. 각 줄에 관련 국 id(`substationIds`) — 광선로는 두 국. 화면이 국별로 묶어 볼 수 있게.
5. 정렬 결정적: 구분(랙→설비→케이블→광선로) → 신설·철거·이설 → 국 이름 → 이름 → id.

- [ ] **Step 1: 실패하는 시험** — 랙 신설·철거·이설(좌표만 바뀜), 랙째 이설 시 안 설비 이설 0, 설비 랙 변경 = 이설 1, 설비 삭제 + 연결 펼침 삭제 = 설비 철거 1 + 케이블 철거 n, 두 국 광선로 신설(긍장 12.5 → 12500 m) + 양 끝 점퍼 2, 긍장 null 「길이 미입력」, 만들었다 지움 = 0 줄, 길이만 바뀐 연결 = 0 줄, rack-install 재료비 산다, 결정성.
- [ ] **Step 2: 실패 확인** — `npx vitest run packages/core`
- [ ] **Step 3: 구현**
- [ ] **Step 4: 통과 확인** — `npx vitest run packages/core && npm run build -w @twin/core`
