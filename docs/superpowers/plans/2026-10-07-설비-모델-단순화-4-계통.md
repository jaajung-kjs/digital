# 설비 모델 단순화 ④ 전원 계통 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 국 탭에 「전원 계통」을 더해 분전반 시트와 전원계통도를 대체한다 — 공급 설비별 **차단기 대장**(현장 분전반 시트 모양)과 **계통도**(입력 전원 → 차단기 → 부하로 이어지는 트리), 교류/직류 거르기.

**Architecture:** 모델·저장은 그대로(차단기 = `Circuit`, 전원 연결 = 차단기 끝 ↔ 설비 끝 `Link`, 방향은 「차단기를 가진 쪽이 공급」 — 스펙). ③과 같은 결: (1) core 순수 파생 `powerTree`, (2) 화면은 그 결과만 그린다. 차단기 편집은 ②의 `CircuitTable`·`BreakerEditor` 칸 편집을 재사용한다. 백엔드 변경 없음.

**Tech Stack:** TypeScript, `@twin/core`(vitest), React 18 + zustand 워킹카피, Tailwind 시맨틱 토큰, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-06-설비-모델-단순화-design.md` — §모델「번호 행」, §국 내 연결(「전원의 방향은 저장하지 않는다 — 회로 행을 가진 쪽이 공급」), §파생「전원 트리」, §화면「계통」, §검증 완료 기준 5.

**현장 양식(근거):** 분전반 시트 머리 「AC입력 : 2층 소내배전반 AC」 + 표 `전압V · CB번호 · 용량A · 부하명 · 전원케이블 · 비고`(`필요자료/2019년강릉전원계통도분전반.xlsx`). 직할 전원계통도 시트는 도형이라 셀 데이터가 없다 — 계통도는 시드 연결(종이 검증 북춘천)과 대조한다.

## Review Focus

1. **순환(A 차단기 → B, B 차단기 → A)** 에서 트리가 무한히 내려가지 않고 그 지점에 「상위 설비로 공급」 표시로 멈춘다. Task 1 시험.
2. **한 설비가 여러 곳에서 전원을 받는**(이중 입력 — 충전기 AC 두 개) 경우 그 설비가 두 부모 밑에 모두 나오되, 그 아래 가지는 한 번만 펼치고 두 번째는 「위에 표시됨」 참조로 둔다(끝없는 중복 방지). Task 1 시험.
3. **교류/직류 거르기**는 차단기 갈래로 가르며, 갈래가 비어 있는 차단기는 「전체」에서만 보인다. Task 1·3 시험.
4. **부하가 없는 차단기(예비)** 도 대장과 계통도에 「예비」로 남는다(사라지지 않는다). Task 1·2 시험.
5. 차단기 대장에서 고친 값이 상세 패널 차단기 요약·편집 창과 **같은 값**이다(한 워킹카피). Task 2 시험.

### Task 1: core — 전원 트리 파생 `powerTree`

**Interfaces — Produces:**

```ts
export type CurrentFilter = 'all' | 'AC' | 'DC';
export interface PowerFeed { equipmentId: string; circuitNo: number; linkId: string }   // 이 설비가 전원을 받는 차단기
export interface PowerNode {
  equipmentId: string;
  feeds: PowerFeed[];                 // 입력 전원(0..n)
  breakers: PowerBreaker[];           // 이 설비의 차단기 1..circuitCount (거르기 적용 후)
}
export interface PowerBreaker {
  no: number; label: string | null; current: string | null; voltage: string | null; capacity: string | null;
  phase: string | null; switch: string | null; purpose: string | null;
  linkId: string | null;              // 이 차단기 끝의 연결
  load: { kind: 'equipment'; equipmentId: string; port: string | null } | { kind: 'other'; ref: LinkEndRef } | null; // null = 예비
  cableTypeId: string | null; lengthM: number | null;
  child: PowerNode | null;            // 부하 설비가 차단기를 가지면 그 아래(재귀)
  repeat: boolean;                    // 이 부하는 이미 다른 가지에서 펼쳤다(Review Focus 2) — child 는 null
  cycle: boolean;                     // 이 부하가 위로 올라가는 길에 이미 있다(Review Focus 1) — child 는 null
}
export function powerTree(input: {
  substationId: string;
  equipment: { id: string; substationId: string; name: string; circuitCount: number }[];
  circuits: { equipmentId: string; no: number; label: string | null; current: string | null; voltage: string | null; capacity: string | null; phase: string | null; switch: string | null; purpose: string | null }[];
  links: { id: string; substationId: string; cableTypeId: string | null; lengthM: number | null; a: LinkEndRef; b: LinkEndRef }[];
  filter: CurrentFilter;
  nameOf: (equipmentId: string) => string;   // 정렬(자연 순서, 숫자 인식)
}): { roots: PowerNode[]; unfed: string[] };
```

규칙:
1. **공급 설비** = 이 국에서 `circuitCount > 0` 인 설비. 차단기 행은 저장된 회로 + `rowsForCount` 기본 행(번호 1..N, 값 null).
2. **입력 전원(feeds)**: 어떤 설비 X 의 **설비 끝**(또는 X 의 차단기 끝이 아닌 X 자신의 끝)이 다른 설비 Y 의 **차단기 끝**과 연결되어 있으면, X 는 Y 차단기 n 에서 전원을 받는다.
3. **뿌리(roots)**: 공급 설비 중 입력 전원이 없는 것 + 입력 전원이 모두 이 국 밖/알 수 없는 것. 정렬 = 이름 자연 순서.
4. **unfed**: 차단기를 가졌는데 입력 전원이 없는 설비 id(뿌리와 같지만 화면에서 「입력 전원 미등록」 표시용으로 따로).
5. 차단기의 `load`: 그 차단기 끝 연결의 반대편 — 설비 끝이면 `{equipment, port: 표기}`, 차단기/코어 끝이면 `other`. 연결 없으면 null(예비).
6. **재귀**: 부하 설비가 차단기를 가지면 `child` 로 내려간다. DFS 경로 집합으로 **순환**(경로에 이미 있음)이면 `cycle: true`, 이미 다른 곳에서 펼친 설비면 `repeat: true`(전역 방문 집합, 뿌리 정렬 순서로 결정적).
7. **거르기**: `AC`/`DC` 면 그 갈래 차단기만, 그리고 그 아래 가지도 같은 거르기. 갈래 null 은 `all` 에서만.
8. 순수 함수 — 저장 없음, 입력 배열 순서에 결과가 흔들리지 않는다(정렬은 이름·번호·id).
