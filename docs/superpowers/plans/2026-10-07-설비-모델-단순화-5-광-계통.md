# 설비 모델 단순화 ⑤ 광 계통·중계경로 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 선번장 코어 사슬에서 **중계경로**(설비 → 코어 → 광선로 → 중계 패치 → … → 설비)를 파생해, ① 선번장·연결에서 한 회선의 중계경로를 추적하고 ② 지사·본부 범위의 **광 계통도**(국 = 마디, 광선로 = 간선 위에 회선 경로를 주회선 실선·예비회선 점선으로)와 **링**·**이중화 경고**를 보인다.

**Architecture:** 망·링 레코드를 두지 않는다(스펙 — 파생). core 순수 함수 `opticalPaths`(사슬 추적) · `pathBundles`(Tx/Rx 묶음) · `rings`(설비-경로 그래프의 고리) · `redundancyWarnings`, 배치는 옛 `topology/layout.ts`(이중연결 성분 → 원·방사, `e5e4ba9e^` 에서 복원해 일반 마디·간선으로)를 재사용. 백엔드는 범위 데이터 한 엔드포인트 `GET /api/v2/nodes/:id/network`(읽기 전용, 추가).

**Tech Stack:** TypeScript, `@twin/core`(vitest), Express + Prisma(읽기), React 18, SVG, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-06-설비-모델-단순화-design.md` — §파생「광 경로」「경로 묶음」「링」「이중화 경고」, §화면「토폴로지·추적」, §검증 완료 기준 3·4.

**현장 어휘(근거):** 소형광 선번장·SCADA 회선현황의 「중계경로」(예 `춘천(구)-(PTP:5)-북춘천`), 「주회선/예비회선」, 강원본부 「OPGW 계통도」, 「예비회선 링 구성도」(`직할/직할+관내변전소+SCADA+RTU+회선현황_250626.xlsx`).

## Review Focus

1. **코어 끝마다 연결은 최대 하나** → 코어에서 출발한 사슬은 유일. 설비에서 출발하면 그 설비의 코어 끝 연결 수만큼. 사슬이 다시 지난 코어 끝으로 돌아오면(데이터 고리) 멈추고 「경로 미완결」. Task 1 시험.
2. **Tx/Rx 두 코어가 한 선**, 주·예비 또는 다른 광선로 순서는 **별개 선**. Task 1 시험(북춘천 송광치 PTP 주 1·2 / 예비 7·8 같은 모양).
3. **이중화 경고**는 같은 설비 쌍의 주·예비 경로가 **같은 광선로를 하나라도 공유**할 때(물리 이중화 아님 — 종이 검증에서 드러난 사실). Task 1 시험.
4. **범위 밖 국**으로 나가는 경로는 끊기지 않고 범위 밖 국까지 그린다(그 국 마디는 흐리게). Task 2·4 시험.
5. 같은 국 안 광선로·같은 광선로 안 점퍼에서도 추적이 맞다. Task 1 시험.

**Interfaces — Produces:**

```ts
export interface PathHop { lineId: string; coreNo: number; from: Side; to: Side }    // 이 광선로 코어를 from 끝 → to 끝으로 지남
export interface PathEnd { equipmentId: string; port: string | null; substationId: string }
export interface OpticalPath {
  id: string;                    // 양끝·홉으로 만든 안정 키
  start: PathEnd | null;         // null = 사슬이 설비에 닿지 않음(빈 코어 끝)
  end: PathEnd | null;
  hops: PathHop[];               // 순서대로
  patches: string[];             // 지난 중계 패치(코어↔코어) 연결 id
  role: 'main' | 'backup' | null;// 지난 코어들의 주/예비가 모두 같으면 그 값, 섞이거나 비면 null
  complete: boolean;             // 양끝이 설비이고 고리 없음
}
export function traceFromCore(net: NetworkInput, at: { lineId: string; coreNo: number; side: Side }): OpticalPath;
export function opticalPaths(net: NetworkInput): OpticalPath[];       // 설비 끝에서 출발하는 모든 사슬(양방향 중복 제거)
export interface PathBundle { id: string; a: PathEnd; b: PathEnd; lineIds: string[]; role: 'main' | 'backup' | null; paths: string[] } // 같은 설비 쌍·광선로 순서·주예비
export function pathBundles(paths: OpticalPath[]): PathBundle[];
export function rings(bundles: PathBundle[]): { id: string; equipmentIds: string[]; bundleIds: string[] }[]; // 설비-묶음 그래프의 고리(이중연결 성분, 마디 3 이상)
export function redundancyWarnings(bundles: PathBundle[]): { a: string; b: string; sharedLineIds: string[]; mainBundle: string; backupBundle: string }[];
export interface NetworkInput {
  lines: { id: string; aSubstationId: string; bSubstationId: string }[];
  cores: { lineId: string; no: number; role: string | null }[];
  links: { id: string; a: LinkEndRef; b: LinkEndRef }[];
  equipmentSubstation: (equipmentId: string) => string | null;
}
export function computeLayout(nodes: { id: string }[], edges: { source: string; target: string }[]): Map<string, { x: number; y: number }>;
```

규칙:
1. **사슬:** 코어 끝 (L, n, s) → 같은 코어의 반대 끝 (L, n, s̄) → 그 끝에 걸린 연결의 반대편: 설비 끝이면 끝(PathEnd), 코어 끝이면 **중계 패치**로 다음 홉, 차단기 끝이면 끝(경로 미완결로 보지 않음 — 설비 끝으로 취급), 없으면 미완결. 시작 쪽도 같은 규칙으로 거슬러 간다(traceFromCore 는 양방향).
2. 방문한 (L, n) 을 다시 만나면 멈추고 `complete=false`.
3. `opticalPaths` 는 설비 끝 ↔ 코어 끝 연결마다 출발, 같은 사슬(양끝·홉 집합 같음)은 하나로. 정렬·키 결정적.
4. **묶음:** (정렬된 양끝 설비 쌍, 지나는 광선로 id 순서(방향 정규화), role) 같으면 한 묶음 — Tx/Rx 가 한 선.
5. **링:** 설비를 마디, 묶음을 간선으로 둔 무향 그래프에서 이중연결 성분(마디 ≥3). 이름 없음.
6. **이중화 경고:** 같은 설비 쌍에 main 묶음과 backup 묶음이 있고 lineIds 교집합이 비지 않으면.
7. `computeLayout` 은 옛 알고리즘 그대로(블록 → 원, 가지 → 방사, 결정적), 시험도 옮긴다.
